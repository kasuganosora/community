# 帖子链接预览

网页时间线与详情页显示链接的标题、摘要、真实域名和可用缩略图。无图或图片加载失败时显示文字卡片；不嵌入第三方脚本、播放器或 iframe。内容警告展开前不补取卡片或加载缩略图。

## 生成与补齐

后端提取帖子的第一个 HTTP(S) 链接，读取 OpenGraph、Twitter、oEmbed 或 HTML 标题。正常 HTML 没有标题时，仅用真实站点名生成基础卡片，不编造视频信息。HTTP 拒绝、DNS/TLS 失败或不符合安全策略时不生成卡片，原链接仍可使用。

新帖通过现有后台队列生成卡片。对于漏掉异步任务的旧帖，网页在帖子进入视口后调用已有的 `GET /api/v1/statuses/:id/card`：后端先校验可见权限，缺卡时异步补齐，立即返回当前卡片或 `null`，不在请求线程里等待远端网站。响应为 `private, no-store`，避免把空结果长期缓存。

前端共用最多 2 个并发请求，保留最多 128 条卡片查询记录；在可见且需要预览时，于 3、8、15 秒最多查询三次，完成记录有效期 60 秒。滚出视口取消后续调度，虚拟行重复挂载复用查询；切换账号会清空记录并取消旧请求。预览完成不会生成一轮全站 Feed 分发或“新帖子”提示。

有附件或引用卡优先的帖子不重复补取链接卡；私信不自动抓取链接。定时和已删除帖子不可通过卡片接口触发抓取。仅关注者可见的帖子必须先通过权限校验。后台队列按帖子去重，卡片记录与正文中的卡片数据在同一事务保存。

## 安全与配置

继续使用受限地址校验和固定 DNS 解析结果的 HTTP 客户端，保留重定向、超时及体积限制。网页最多读取约 1 MiB 的前缀；前缀已包含标题的长页面可正常预览。预览图片经后端下载存储或媒体代理，不直接使用第三方图片请求暴露浏览者信息。标题和描述按纯文本渲染。

环境变量沿用现有配置：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `LINK_CARDS_ENABLED` | 开启 | `false`、`0` 或 `off` 禁止后台生成与补齐 |
| `LINK_CARD_WORKERS` | 2 | 后台并发 |
| `LINK_CARD_QUEUE` | 256 | 有界队列容量 |
| `LINK_CARD_RATE_PER_SEC` | 5 | 每秒处理上限 |

管理员也可使用 `tootctl link-cards backfill` 补齐历史数据，具体参数见命令帮助。视频网站可能返回验证码页面或拒绝抓取；卡片展示实际取得的信息，不绕过这些限制。

## 本轮真实验证（2026-10-11）

使用保留的真实 Misskey 实验网页验证有图、无图、失败响应和旧帖漏任务恢复。图片经本站接口返回有效 PNG，私密帖的匿名及非收件人请求被拒绝，私信保持无预览。浏览器实际观察旧帖从 `card=null` 经补取后出现卡片，无需刷新；内容警告关闭时不请求，展开后的失败请求达到三次后停止。1280、390、320 宽度的浅深色页面无横向溢出，受控坏图不影响文字链接。

截图中的 Bilibili 链接已尝试，但本次环境未成功生成其卡片；不将实验网页的通过结果冒称为该视频抓取成功。原始 API、浏览器及构建记录位于本次工作区 `/tmp/community-linkcard-qa/`，私有账号和凭据不入仓库。

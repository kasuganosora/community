# Community 网页 Matrix 群组实施计划（修订版）

更新：2026-10-13。状态：已实施。本文保留设计和验收要求；实际完成范围、测量环境及已知限制见[验收报告](matrix-web-groups-validation.md)，接口与部署说明见[运维文档](../matrix-web-groups.md)。

## 1. 产品边界

- 群聊参与者为 Community 本地用户及 Matrix 用户。网页登录继续使用 Community 登录态，不在网页建立外部 Matrix 账号登录系统。
- Community 本地用户使用与其现有 Matrix 客户端相同的身份，群成员、未读与消息应跨端一致。
- 网页创建的群不启用端到端加密；创建页明确提示。非加密仍使用 HTTPS 与 Matrix 联邦传输机制，不称为私密加密聊天。
- 不接入本站 ActivityPub 私信桥接，不邀请本站 AP ghost 或桥接控制账号，不创建 AP Status 或 AP 投递任务。
- 外部 Matrix 成员一律作为普通 Matrix 成员，不识别或限制对方安装的桥接。
- 首期支持文本、链接、成员提及、回复、删除、删除后重发、图片、通用文件、Unicode 表情、自定义表情、消息回应、未读、已读位置和输入状态。
- 本期不做音视频通话、会议、屏幕共享、录音、视频播放器、转码和媒体编辑器。收到音视频事件可显示基本附件信息并提供下载／客户端入口，不自动播放；通话等事件显示简短不支持提示，不输出原始事件 JSON。
- 文件大小、类型与数量采用明确配置；上传图片与普通附件不等于支持视频功能。

## 2. 审查发现与架构修正

| 初版隐患 | 修订决策 |
| --- | --- |
| 假设已有群组接口可直接包装 | `controllers/api/group/group.go`、`models/group.go` 是另一套 Group/Member/Message 存储，并有桥接失败降级本地逻辑；新功能不走此路径 |
| 假设已有网页会话接口是纯 Matrix | `/api/v1/chat/conversations` 使用 AP 桥接会话与 Status、投递映射；群组独立使用原生 Matrix 服务，不把桥接会话扩展为原生群 |
| 假设已有实时链路可直接用于群聊 | 当前 `useChatThread.ts` 是定时拉取最近消息；须补充持久化增量游标、断线补偿及网页通知适配 |
| 把目录公开等同于公开加入 | 房间目录可见性、加入规则、历史可见性分别建模和授权 |
| 假设 publicRooms 可直接远端搜索及分页 | 当前 client publicRooms 主要查本地，游标未完成过滤；联邦目录还需修正公开条件，增加远端查询与完整分页 |
| 假设申请加入已具备外部支持 | 当前 knock handler 主要直接处理本地房间；外部解析、联邦申请、撤销与审批状态需要真实实现和验证 |
| 承诺入群前一定知道是否加密 | 公开目录不保证提供加密状态；支持未知状态，以及加入后发现加密的准确反馈 |
| 承诺所有客户端表情和文件表现一致 | 明确标准能力、扩展能力与降级展示，分别验收 |
| 承诺撤回后附件全网不可读 | 网页入口执行可见性授权；无法收回远端副本、截图或已经下载的文件 |

### 实现结构

网页群聊 API → 应用层授权与 DTO → 现有 Matrix Room / Event / Sync / Relations / Media 服务 → Matrix 联邦。

- 不新增独立桥接服务、额外消息数据库、独立搜索集群或每用户后台轮询 worker。
- Matrix 表与事件为成员、权限、消息的唯一权威来源；Community 只增加必要的群组关联、用户偏好、幂等记录、操作状态与可重建读模型。
- 新路由统一为 `/api/v1/chat/groups`，复用并审查现有 Community 身份认证入口。不能仅因使用网页专用路由便放宽身份、scope、CSRF（如使用 cookie）与对象授权。
- 检查当前 Matrix 用户初始化，不能只拼接 MXID 就假定账号和成员身份存在。群组创建失败不返回“本地创建成功”。
- 身份 ID、游标与资源引用可作为不透明字符串传递；网页不处理 Matrix token、原始事件、homeserver 发现或协议错误。隐藏协议细节是产品边界，不是安全边界。
- 首阶段盘点旧群组路由调用方和存量数据，避免网页同时暴露两个群组入口。旧群组和 AP 会话接口保持独立；新网页不写入它们，也不在本次静默迁移或删除旧数据。旧路径不能借新群 ID 访问新房间。

## 3. 房间、权限与生命周期

### 创建默认值

- 默认仅邀请、目录不公开、历史仅加入后可见、不启用访客、不启用加密。
- 用户选择公开群时，明确允许直接加入和在本站目录展示；不自动把历史设为任何人可读。
- 首期创建仅提供“公开”及“仅邀请”两个简明选项；外部房间照其实际加入规则处理。
- 沿用服务器已验证的房间默认版本和能力协商，不在网页硬编码版本或默认自动升级。

### 加入与成员状态

- 接受群别名、`matrix.to` 链接和 `matrix:` URI；保留经校验的 via 提示。无服务器后缀的房间 ID 不能靠拆 ID 猜服务器。
- 预览、精确解析均为只读，绝不因搜索、打开预览或链接就自动加入。
- 状态至少包含：未加入、邀请待处理、正在加入、等待批准、已加入、已离开、被封禁、失败／待核实。
- 超时不一定代表远端没有接受；重试前校验当前成员状态，避免重复操作或错误提示。
- 公开加入、接受／拒绝邀请、申请／撤销申请、退出、踢人、封禁／解封、邀请、修改名称头像介绍纳入范围。
- restricted / knock_restricted 等受限规则按实际能力与资格处理；不能把所有禁止加入都转换成“申请”。资格不足或不支持时提供具体说明及客户端入口。
- 普通群退出后立即移出活跃列表，不因新消息自动拉回；明确的新邀请作为邀请展示。
- 不提供“删除整个群”承诺。退出、隐藏历史和全网销毁不是一回事。
- 收到升级／替代房间事件时，网页将旧房间设为只读，提示并提供查看或加入新房间的操作，不自动加入或合并历史。Spaces 不当作普通聊天群打开；本期不做空间树和层级管理。

### 权限

- 成员查找支持本站用户和完整 Matrix ID，输入类型明确，不把 `用户名@域名` 自动当作 AP 用户解析；远端昵称仅用于展示，邀请以规范化身份为准。
- 房间缺少名称／头像时使用明确的默认名称及算法头像；有房间状态时优先显示房间头像，不借群成员中任意一人的头像代表群。

- API 返回按操作计算的 capabilities，例如 send_message、invite、kick、ban、redact、set_name、set_avatar、manage_permissions。
- 每次写入仍以后端 Matrix 授权为准，前端按钮和缓存不是授权依据；未知／未验证状态下停止敏感操作。
- 不仅用“群主／管理员／成员”三种名称推导权限。外部房间自定义 power levels 及新版本创建者特权可能不同。
- 提供可安全执行的管理员设置；不能承诺可降级创建者、转让所有权或修改超过本人权限的成员。
- 本站 AP ghost／系统账号过滤依据本地明确的身份记录，不按字符串猜测外部用户类型。

## 4. 加密边界

- 网页创建请求不接受加密配置；网页不提供启用加密的管理操作。
- 有权使用原生客户端的人以后可能启用房间加密，所以不能把“网页创建时非加密”误写成“永久禁止加密”。
- 加密状态为 unknown / unencrypted / encrypted；不能将查不到状态等同于非加密。
- 在查询到加密状态前禁用发送及上传；识别加密群后提示“请使用 Matrix 客户端”，提供复制地址、客户端入口及退出／拒绝邀请操作。
- 若必须加入后才能知道加密状态，准确显示“已加入，请使用客户端”；不静默退群，也不显示加入失败。
- 收到启用加密事件后立即停止网页发送和上传；未发送草稿保留供复制，待重试任务不得自动明文重发。上传完成但尚未引用的文件也不得自动发进已加密房间。
- 发送服务与状态检查应共享一致的本地事务／锁边界，禁止在已知加密状态下提交明文。
- 联邦状态传播存在延迟，无法承诺在本站尚未获知远端加密事件时零竞争窗口；不把网页当作 E2EE 客户端，不解密或伪造密钥能力。

## 5. 群组搜索与发现

### 搜索入口

网页统一搜索增加“群组”类型，调用专用群搜索服务；不向 Mastodon 兼容的搜索响应随意塞入新类型。

- 默认范围为我的群组与本站公开目录；用户可切换范围，选择一台外部服务器查询其公开目录。
- 不在每次输入时无提示地向多个外部服务器广播关键词。不宣传覆盖全网。
- 精确群别名／链接单独解析，不要求目标必须出现在公开目录。
- 远端目录不提供可靠的“源站所有权”信息：标注目录来源／别名域名，不把去中心化房间声称为某服务器独占。
- 已加入私密群只在本人“我的群组”范围显示；外部目录只显示其公开提供的元数据；未加入时不预拉消息或成员名单。
- 不提供外部群消息全文检索，不依赖抓取整个目录来实现关键词搜索。

### 搜索与展示约束

- 区分目录不可用／不开放／限流／超时／确实无结果；成员数、加密状态、简介等缺失时显示未知，而非猜测。
- 后端以 room ID 去重，不以名称或别名去重；昵称与群名按不可信文本处理，HTML 必须净化。
- 各范围独立分页；游标绑定用户、查询、范围和服务器，远端分页 token 不混用。本期不做跨全网混排排序。
- 公开目录可以短暂缓存；个人群列表、邀请和搜索结果不能进入共享公共缓存。
- 远端解析、目录、媒体与重定向统一使用安全的 Matrix 服务器发现及出站规则；校验 serverName、DNS 结果、IPv6、端口及每次跳转，禁止私网探测。管理员明确配置的实验服务器例外独立管理。
- 请求有总时限、并发限额、响应字节上限、取消和限流。网络请求不占用长数据库事务。

## 6. 消息、表情、媒体

### 消息

- 支持普通文本、链接、成员提及、回复、历史分页、删除本人消息和按权限删除他人消息。
- 提及使用明确成员标识；本期不默认提供全群广播提及。通知遵循房间静音与用户偏好。
- 网页编辑始终是“删除并重发”，明确提示。两步并非跨联邦原子操作：记录原消息删除和新消息发送的独立结果，部分失败时可恢复，不伪报成功。原消息的回复与回应不能伪造迁移到新事件。
- 外部客户端发送的有效编辑需要正确展示最新内容与已编辑标记；这不等于网页提供原地编辑。
- 外部线程回复可降级为带上下文的普通回复，不丢弃消息；本期不实现独立线程界面。回复目标不可读／已删除时显示占位，不绕过历史权限获取上下文。
- 未知消息类型保持时间线连续并显示适当占位，不将协议 JSON 或未经净化的远端 HTML直接呈现。
- 发送幂等键按用户、房间与事务隔离；同键不同内容返回冲突，超时重试同键不得产生第二条事件。
- UI 的“已发送”表示本地服务已持久化／接受，不能等同于全部远端收件人收到。已读回执缺失不意味着未读，也不承诺完整人员名单。

### 表情

- Unicode 消息与 reaction 作为跨客户端基线；支持添加和撤销自己的 reaction，以有效发送者／目标／表情聚合，处理撤回和重放。
- 自定义表情正文发送兼容的图像表现及文字替代，不发送只有本站能识别的裸 shortcode。
- 自定义 reaction 采用已有通行扩展并实测 Element；不支持图片扩展的客户端允许显示文字或链接替代，不承诺显示完全一致。

### 图片与文件

- 图片支持选择、拖拽／粘贴、预览、查看原图、下载；普通文件显示名称、类型、大小、进度、取消与重试。
- 上传直接复用 Matrix 媒体服务，不使用 ActivityPub MediaAttachment 的公开地址承载群内附件。
- 上传与发送分离；上传完成不代表消息已发送。引用附件时检查上传者、有效期、房间及当前发送权限。
- 多附件可能对应多条 Matrix 事件；每个附件子事务单独幂等，部分成功时只重试失败项，不重复发送全部附件。
- 文件流式上传／下载，限制总大小、并发、响应大小、图片像素与缩略图资源，不把大文件整体缓存在内存。
- 校验实际类型及文件名；SVG、HTML 等危险内容禁止以内联可执行文档呈现，返回安全 Content-Disposition 与 nosniff。
- Community 网页媒体入口关联房间事件并遵守其可见性；不能把“已登录 Matrix”当作可访问任意群附件的依据。
- 已交付给远端或下载的媒体无法全网撤回；删除消息不等于删除所有文件副本，退出／踢人也无法收回既有副本。
- 上传后未使用的附件设置 TTL 清理，不能误删仍被事件引用的媒体；权限变更后终止尚未开始的发送，必要时清理临时上传。

## 7. 同步、性能与接口

### 同步方案

- 群消息写入沿用 Matrix 事件持久化和联邦投递路径；通知可复用现有 Redis／事件机制，可靠性依赖持久化事件与游标而非 Pub/Sub 本身。
- 提供网页 DTO 形式的增量同步，覆盖新消息、删除、编辑、回应、成员、权限、加密状态、邀请和已读位置。
- 初始快照必须带一致的同步水位；实时通知只是唤醒，重连／漏通知从持久化游标补齐，处理游标过期的重新同步流程。
- 区分全局增量游标与单房间历史游标；历史按服务端稳定流序分页，不以客户端时间排序去重，不从最近 40 条推断完整增量。
- 每个网页会话最多一条群聊事件通道，不为每个群开启轮询；多实例下通知可跨节点传播。成员状态撤销后关闭其不再有权访问的流。
- 记录加入与目录查询耗时／失败类型、同步延迟、发送重试、媒体失败与队列积压；日志不记录 token、私聊正文或密钥，以请求 ID 关联排障。
- 首期采用 SSE 或等价的现有长轮询基础设施，实施阶段依据现有事件服务选定一种，不同时建设两套。
- 分页加载会话、历史与成员；读模型批量取头像、最后消息、未读，避免每个群／成员额外发一次 SQL 或远端请求。
- 复用 Matrix 回执和账户数据处理跨端已读、会话归类及静音，避免另建一套相互冲突的未读事实。

### 接口草案

| 操作 | 接口方向 |
| --- | --- |
| 我的群组、创建 | `GET/POST /api/v1/chat/groups` |
| 搜索与只读解析 | `GET /groups/search`、`POST /groups/resolve` |
| 加入／申请／接受邀请 | `POST /groups/join`；明确操作类型、幂等键与目标引用 |
| 群详情和能力 | `GET /groups/:id` |
| 名称、简介、头像等 | `PATCH /groups/:id`，仅接受白名单字段 |
| 成员、邀请、审批及管理 | `/groups/:id/members`、对应动作子资源；不能借任意 state API 绕过权限 |
| 历史与发送 | `GET/POST /groups/:id/messages` |
| 删除／删除后重发、回应 | 消息的对应子资源 |
| 上传／下载 | `/groups/:id/uploads` 及与可见消息关联的媒体接口 |
| 已读、输入与会话偏好 | 房间对应子资源 |
| 退出／取消申请／拒绝邀请 | 显式操作接口，不混用为“删除群” |
| 增量同步与事件通道 | `/api/v1/chat/group-sync` 与事件订阅入口 |

短路径均位于 `/api/v1/chat` 下。实施前固化请求／响应契约、错误码、capabilities、同步水位、媒体授权及分页上限。网页不接受客户端自报的发送者身份或管理权限。

## 8. 实施顺序与交付门槛

1. **协议和授权基线**：修复目录公开条件、分页与远端目录；核实本地身份、联邦加入、历史权限与媒体入口；验证外部 knock／restricted 状态。通过后进入网页实现，不以 UI 掩盖缺失协议能力。
2. **原生群应用层**：新增群服务及 DTO，创建／解析／加入／邀请／权限／退出／加密边界；明确与旧 groups、AP conversations 的隔离。失败无本地降级假成功。
3. **消息与同步**：完成持久化增量、幂等、历史、删除／重发、回应、回执；验证两后端实例下通知与重连。
4. **媒体和兼容渲染**：上传、附件子事务、受控下载、表情、外部编辑与未知类型降级；验证权限与资源上限。
5. **网页与统一搜索**：消息页增加群聊，创建／加入流程、详情、成员管理、搜索分类和来源选择；按 Apple 设计原则复核深浅色、手机、键盘、错误／加载／空状态。
6. **联调与回归交付**：修复所有阻断问题，形成联调证据、性能基线、运维配置、限制说明及回滚方案，按既定流程提交到 master。回滚不删除已经存在的 Matrix 房间和消息。

各阶段以实际验收证据为准，不能仅凭计划条目判断所有远端服务器、客户端或部署环境均已兼容。结果与未覆盖项记录在[验收报告](matrix-web-groups-validation.md)。

## 9. 验收矩阵

- 至少两个 Community 本地账号、两个外部 Matrix 测试账号；网页与 Element 交叉操作，覆盖本站群和外部服务器群。
- 本站公开／邀请群创建，成员邀请、拒绝、重新邀请、申请／撤销、批准、退出、踢人、封禁／解封；外部 restricted 资格不足不错误显示可申请。
- 精确别名／两种链接解析、via 保留、目录公开与加入规则分离、外部搜索与分页、同房间多个别名去重、私密群仅本人可搜。
- Matrix v12 等无域名房间 ID 与受支持版本协商；替代房间提示、Spaces 不误当普通群。
- 中英文、链接、提及、回复、Unicode／自定义表情、reaction 添加／撤回、外部编辑、未知事件；消息删除和删除后重发部分失败可恢复。
- 图片与文件双向传输，校验文件完整性；多附件部分失败不重复成功项，大小与类型限制、取消、超时重试、远端媒体不可用有明确反馈。
- 非成员／被踢成员无法通过本站网页 API 获取无权读取的历史、回复上下文或附件；共享缓存不跨用户泄漏。按实际历史策略测试离开后的历史访问，不一概假定离开即删除全部历史。
- 加密 unknown 状态不可发送；已加密入群准确提示；群中启用加密阻止已知状态下的明文和排队重发；客户端入口不携带 access token。
- 断线与重启、远端时钟偏移、同毫秒并发、旧页编辑／删除、联邦回填、事件重复与乱序到达、同步游标过期、首屏与订阅竞争窗口、多个设备已读同步；退出群后无新消息触发的自动加入。
- 权限变更立即反映在授权；并发重试同事务只产生一条消息，伪造客户端身份或管理参数无效。
- 本站群操作不生成 AP Status／投递；外部桥接成员不识别不限制；原 AP 私信继续工作。
- 320／390／768／1440／1920 宽度，深浅色、键盘、读屏标签、减少动态效果；长群名、文件名、成员名不撑破布局。
- 在固定环境记录 100 个群、单群 10,000 条历史、100 个在线网页连接的基线；检查会话／成员批量查询无 N+1、历史最多按页加载、无每房间定时轮询、大文件内存有界、重连期间不漏不重。记录 P50/P95、SQL、连接与 RSS；吞吐目标按实际硬件基线确定，不承诺任意硬件的固定数字。
- 所有测试保留可复现步骤和失败证据。外部生产大群不用于无授权压力测试，性能数据使用实验服务器和假数据。

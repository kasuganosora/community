# 后台布局与设置表单视觉审查（2026-10-11）

本轮重点修复 `/admin/settings/*` 的空间分配、字段对齐和控件状态。依据 [Apple design skill](https://github.com/emilkowalski/skills/blob/e8a175de22ae1e49370fc144c1f3bb9aeedf988d/skills/apple-design/SKILL.md) 的层级、分组、排版和可访问性原则，并按 [Emil design engineering skill](https://github.com/emilkowalski/skills/blob/e8a175de22ae1e49370fc144c1f3bb9aeedf988d/skills/emil-design-eng/SKILL.md) 记录前后对比；沿用现有 Vue 组件与原生控件。

## 文件与视觉审查

| Before | After | Why |
| --- | --- | --- |
| 内容容器和表单分别限宽，宽屏出现两层右侧空白 | 设置卡片使用可用内容宽度，桌面采用左侧标签说明、右侧控件的整行布局 | 控件和卡片边界统一，避免输入框只占卡片一部分 |
| 标签、提示、按钮缺少稳定的分组与对齐 | 字段行使用统一内边距与分隔线，底部集中保存操作 | 使字段关联和操作位置容易辨认 |
| 多行文本框拉开标签与说明距离 | 标签与说明紧邻，控件跨两行布局 | 长控件不再破坏文字层级 |
| 通用输入选择器覆盖只读和按钮样式 | 降低基础选择器优先级，统一控件背景、边框及状态 | 明确区分可编辑、只读、禁用与焦点状态 |
| 不同设置页的布尔控件表现不统一 | 设置使用基于原生 checkbox 的 switch，角色权限保留复选框 | 保持语义和键盘操作，同时统一设置交互 |
| 小屏卡片与字段叠加内边距，控件过窄 | 手机使用单列字段及单层内边距，粗指针目标至少 44px | 保留可用输入空间，降低误触 |
| 侧栏整体滚动，当前项可能不在视野 | 品牌与底部固定，导航独立滚动并定位当前项 | 长导航仍能保持方向感 |
| 侧栏外观切换占用空间 | 按要求移除，继续使用全站主题 | 精简后台常驻操作 |
| 概览信息继承不适合其结构的两列网格 | 每条信息独立对齐，分析图表按屏宽分栏 | 避免信息错列和过长的纵向堆叠 |

主要文件：`layouts/admin.css` 统一布局及响应式规则；`AdminField.vue` 增加控件容器并修复无提示时的 ARIA 引用；`AdminCheck.vue` 提供可选 switch；`SettingsCenterPage.vue` 和 `SettingsAdminPage.vue` 统一设置布局；`AdminLayout.vue` 精简侧栏并定位当前导航。概览、分析及角色页同步调整共享布局。CSS 展开为可读格式，便于后续维护。

## 验证

- 前端类型检查、Vite 生产构建、后台 ESLint 和 `git diff --check` 通过。
- 后台单元测试：18 个文件、70 个测试通过。
- 全后台 27 个导航页面在 1440 浅色／深色、1024 浅色、390 深色及 320 浅色下完成 146 项浏览器检查。
- 最终设置页专项回归：9 个设置页面在上述尺寸下完成 96 项检查；另在 1920 深色及 2560 浅色完成 36 项检查。无页面脚本异常、请求错误或横向溢出；验证了桌面字段对齐、小屏上下排列及导航操作。
- 13 项交互检查通过，包括真实保存站点名称并通过认证 API 验证持久化、只读字段、密钥输入类型、键盘开关、焦点、无修改时禁用保存及减少动态效果。保存测试在 finally 中恢复原名称。
- 实际查看了概览、角色、用户及设置页截图，重点复核宽屏常规／品牌、深色存储和手机安全表单。触屏检查使用浏览器模拟，未进行物理手机测试。

临时证据位于 QA 环境 `/tmp/community-admin-visual-qa/`：`review.json`、`settings-review.json`、`wide-review.json`、`interactions.json`、构建／测试日志及各尺寸截图。临时凭据未纳入仓库。

本轮是前端布局及交互改进；部署配置只读、密钥保留／清除等后端约束不变。未以样式检查代替 SMTP、S3 或联邦服务的端到端验证，也未部署到生产环境。

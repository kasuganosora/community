# 群组独立模块与统一搜索审查

日期：2026-10-14。审查依据为项目现有设计变量、路由和草稿保护，以及用户指定的 Emil Kowalski `emil-design-eng` 设计技能。此次优先减少重复入口、保持可预测的导航与键盘操作，不新增装饰性动效。

## 设计与交互

| Before | After | Why |
| --- | --- | --- |
| 群列表同时有“加入”、发现图标和只筛选当前已加载列表的搜索框 | 复用统一 `SearchBox`，默认搜索群组；群名与群地址都在同一入口提交 | 减少重复控件，用户不必先判断该用哪一种入口 |
| 搜索结果页自写搜索表单，桌面右栏还出现第二个搜索框 | 结果页复用 `SearchBox`，隐藏右栏重复搜索框 | 同一页面只保留一个输入状态，明确查询与结果的关系 |
| 群聊放在 `/messages/groups`，与私信共享“消息”标题和切换标签 | 独立 `/groups` 与 `/groups/:groupId`，独立群组模块与导航；消息页只保留私信 | 明确群聊和私信的不同使用场景，减少交叉导航 |
| 群列表没有右栏，移动端也不显示右栏搜索 | 群列表使用同一个共享搜索组件；窄屏群会话返回列表即可搜索 | 合并功能后仍保留可见且可访问的入口 |
| 搜索结果跳到另一个加入面板，再次确认地址 | 搜索结果中预览群信息并明确加入或申请，成功后可直接打开群聊 | 消除第二套加入界面，同时不把搜索或预览变成自动入群 |
| 本地列表筛选仅覆盖已加载的 40 个群 | 使用统一搜索已有的服务器端“我的群组”范围及分页 | 不漏掉尚未滚动加载的已加入群，也不暴露他人的私密群 |
| 共享搜索按钮约 32px 高、输入框 44px 高，窄列表中提示文字截断 | 搜索按钮使用相同的最小触控高度，群列表提示简化为“群名或群地址” | 控件对齐且手机更易点击，短提示仍明确支持地址 |

## 必须保留的行为

- 旧 `/messages/groups` 和房间深链接重定向到新位置，保留编码后的房间 ID、查询参数和片段；旧加入链接保留 `join`、`via[]`、`preview`，转入统一搜索预览。路由不能被 `/messages/:conversationId` 误识别为私信。
- 输入、搜索、地址解析都不调用加入接口。加入、申请、邀请、等待处理、失败重试和加密群客户端提示仍有明确状态；已经加入的群直接打开。
- `!opaque` 类型房间 ID 不一定含服务器名，`via` 和目录返回的 `preview_ref` 不可在页面跳转或再次解析时丢失。
- 搜索和导航通过 Vue Router；现有未发送文本、附件的离开确认继续生效，取消导航后草稿保留。
- 私密群结果在退出账号或切换账号后立即失效；旧异步响应不可覆盖新会话。外部目录仅向用户明确选择的服务器发送搜索词。
- 创建群的非加密确认、本站成员提示、权限限制，以及群升级后的“查看新群”入口保留。

## 验收范围与结果

验收使用本地真实 Vue 页面与 Chromium，受控 API 响应用于可重复覆盖路由、交互和异常分支。这不是外部 Matrix 联邦端到端验收。

| 场景 | 验收要求 | 状态 |
| --- | --- | --- |
| 桌面与 390px 移动端群列表 | 只有一个共享搜索框，无独立加入/发现图标和旧列表过滤，无横向溢出 | 通过 |
| 统一搜索结果 | 一个输入框，群组范围含我的群组/本站公开群；普通查询及地址解析行为正确 | 通过 |
| 群地址与旧链接 | 群 ID、多个 `via`、`preview` 完整保留；预览不自动加入 | 通过 |
| 已加入与新群 | 已加入直接打开；新群显式操作后只提交一次加入，再可打开群聊 | 通过 |
| 未发送草稿 | 从当前群搜索时出现离开确认，取消后文本与已上传待发送附件仍保留 | 通过 |
| 模块与导航 | 群组侧栏正确高亮，私信页没有群聊标签或建群按钮，旧路径可用；手机“我→群组”可进入独立模块 | 通过 |
| 键盘与布局 | 搜索 Enter 提交；共享输入框/按钮对齐，群列表与结果页无横向溢出 | 通过 |

初次浏览器检查发现共享 `SearchBox` 的可选 Boolean 属性 `navigate` 未设置默认值。Vue 将未传入的 Boolean 属性转换为 `false`，导致群页、探索页和右栏的搜索只触发事件、不执行路由跳转；Enter 和点击搜索都会失败。搜索结果页使用自己的事件处理，因此单独检查结果页无法发现此问题。现已将 `navigate` 显式默认设为 `true`，并保留结果页明确传入 `false` 的受控提交方式；浏览器重新验证群页 Enter 导航通过。

最终浏览器脚本通过 **41 项检查**，覆盖 1440×1040 浅色和 390×844 深色，未出现未捕获 JavaScript 错误、Vue 运行时错误或源码请求失败。已人工查看群列表、统一搜索结果与精确地址预览的桌面/手机截图。受控数据下的加入、路由与草稿交互通过；外部 Matrix 实例是否实际接受加入不属于本次前端验收结论。

本地证据：`/tmp/community-unified-search-browser/report.json`、同目录的 `groups-*` / `search-*` / `reference-*` 截图；脚本为 `/tmp/community-unified-search-browser.mjs`。开发环境浏览器运行时的 API 响应为固定合成数据，不包含真实账号密钥或私信。

## 追加审查：群组搜索卡片简化

| Before | After | Why |
| --- | --- | --- |
| 地址预览前另有解释段落，未知群同时堆叠信息缺失提示与多个操作 | 不重复添加预览前言；无群资料时只保留一条条件说明和“加入群组” | 让主要操作清楚，同时不把未知状态表述成已确认的加密群 |
| 头像占据正文左侧空间，介绍和操作挤在窄列 | 头像与标题、已知元信息组成顶部一行；介绍独占整行，操作在底部 | 手机长名称、长介绍有足够阅读宽度 |
| 加入、申请和客户端入口可能同时出现 | 按已知加入规则显示单个操作：加入、申请、接受邀请；加入加密群后只显示客户端入口 | 避免用户猜测不同按钮的意义，也避免暗示网页可以读取加密消息 |
| 缺失成员数也显示占位元信息 | 不显示“成员数未知”；有群资料但加密状态未确认时仍保留准确的待确认标记 | 去掉低价值占位信息，保留影响聊天能力的状态 |

本次追加执行 1440px 浅色、390px 深色及 320px 浅色下的无群资料、公开群、申请群、受邀群、已知加密群，共 **15 个预览/操作场景**（142 项断言），全部通过。检查覆盖：每张预览卡片只有一个操作、预览不自动入群、`join` / `knock` 请求与路由提示正确、申请后只显示等待状态、加密群加入后仅显示客户端链接、按钮至少 44px 且键盘焦点可见、正文横跨卡片并位于头部之后、没有横向溢出。浏览器与 Vue 控制台无错误；已人工查看上述宽度的代表性截图，未发现对齐或裁切问题。

边界：未获得群规则时仅尝试显式 `join`；已知 `knock` / `knock_restricted` 才选择申请。系统不会因为普通 403 自动切换为申请，不能据此宣称能自动识别所有外部审批群。测试使用受控 API，不代表真实外部群组接受加入。

追加证据：`/tmp/community-group-card-review/report.json`、同目录的各状态截图；脚本为 `/tmp/community-group-card-review.mjs`。这是卡片简化的追加验收，不是重复计算前述 41 项统一搜索检查。

## 追加审查：共享搜索输入细节

| Before | After | Why |
| --- | --- | --- |
| 搜索外壳已有聚焦环，内部原生输入又被通用焦点规则加上矩形轮廓 | 通过共享 TDesign 覆盖统一去掉内部轮廓，保留外壳焦点环；按钮仍保留自己的键盘焦点 | 同一个输入只出现一层清晰聚焦状态，键盘操作仍可辨识 |
| 内置清除图标依赖鼠标点击，缺少独立键盘入口 | 使用有“清除搜索”名称的原生按钮，支持 Tab、Enter，清除后焦点回到输入 | 不必切换鼠标即可重新输入，也不误触搜索提交 |
| 组件上的可访问名称落在包装层，未命名实际输入 | 通过 TDesign 的公开输入引用给原生搜索输入命名 | 辅助技术能正确识别搜索控件 |
| 触控清除面积与后缀间距不明确，原生搜索控件可能重复出现清除装饰 | 图标不压缩、末端留白统一，触控清除区域为 44px，关闭浏览器搜索装饰 | 保留文字编辑空间，窄屏可点击且只有一个清除入口 |

本次在 1440px 浅色、390px 深色与 320px 浅色下检查群组页及统一搜索结果页，共 **81 项浏览器断言通过**。实测原生输入的 `outline` 与 `box-shadow` 均为 `none`，外壳保持聚焦环；确认清除按钮键盘可达、焦点可见、清除不提交且重新聚焦，中文输入法组合期间 Enter 不导航，组合结束后正常提交。手机输入字号为 16px、清除触控区域至少 44px，无横向溢出。已人工查看对应桌面和手机截图，未发现双重蓝框、重复清除图标、文本与图标重叠或裁切。

`SearchBox` 的 5 个定向行为测试与 ESLint 通过，新增测试只覆盖清除及焦点行为；浏览器控制台无错误。验收仍使用真实 Vue 页面和受控 API，不涉及真实联邦请求。证据：`/tmp/community-search-input-review/report.json`、同目录 `groups-focus-*` / `search-focus-*` 截图，脚本 `/tmp/community-search-input-review.mjs`。

# 网页 Matrix 群组验收记录

日期：2026-10-13。实施前已将 `master` 从 `107ee17` 快进到远端 `87b6023`。本次新增 `/messages/groups` 和统一搜索的群组类型，复用原生 Matrix 房间、事件、媒体和联邦投递；没有引入独立消息服务或浏览器 Matrix SDK。

## 已实现范围

- 非加密公开／邀请群，明确的创建确认；只读预览、别名及链接解析、加入／申请、邀请／审批、退出、踢人、封禁和权限管理。
- 我的群组、本站目录及用户指定的远端目录搜索。搜索不自动加入、不读取未加入私密群的内容、不向多台服务器广播查询。
- 文本、提及、回复、分页历史、删除／明确告知的删除并重发、外部编辑、普通及自定义表情／回应、图片和文件。
- 持久化长轮询游标、幂等重试、未读／已读、输入提示、静音、断线补偿；手机与桌面布局。
- 网页仅使用 Community 登录态。本站 AP ghost／桥接会话不接入群组，外部 Matrix 桥接成员按普通成员处理。
- 加密未知／已加密群禁止网页明文发送及上传，保留草稿并提供客户端入口；加入后才发现加密时准确展示已加入。无音视频通话、录音、播放器或转码。

接口、限制、部署及回退步骤见[运维文档](../matrix-web-groups.md)；界面审查见[设计审查记录](matrix-web-groups-ui-review.md)。

## 验证环境与隔离

本站接口和联邦实验分别使用三个新建 Community 账号，联邦另建两个 Synapse 账号。独立 MySQL 测试库位于实验实例，Redis 使用独立逻辑库；没有读写生产用户的群数据。真实联邦使用 Synapse **1.162.0**、实验域名、HTTPS 和实验 CA；Element 使用现有实验容器，通过 Chromium 实际登录和操作。

临时脚本、截图和原始报告保留在本次工作环境 `/tmp/community-groups-qa/`，不提交凭据、数据库、浏览器 profile 或二进制。它们不是永久 CI 附件，重建环境后需重新准备。仓库内保留协议、授权、并发、媒体和界面的自动回归。临时联邦反向代理映射在验收后已恢复，原有服务数据保留。

该云环境根盘空间耗尽，SQLite 默认选择 `/var/tmp` 时发生临时文件 `ENOSPC`。通过系统调用跟踪确认后，仅将任务环境的 `SQLITE_TMPDIR` 和 `TMPDIR` 指向有空间的 `/tmp`，迁移包连续 3 次通过；未修改迁移逻辑或放宽断言。

## 性能基线

这是共享实验环境测量，不是生产容量承诺。容器配额为 **4 CPU、32 GiB 内存**，后端 `GOMAXPROCS=2`、release 模式，MySQL InnoDB buffer pool 256 MiB，其他验收进程同时运行。

通过真实 API 创建 100 个私密群。在其中一个仅有测试用户的群写入 10,000 条明确标记的本地历史测试数据，并附实际历史状态引用，未将这些未签名数据联邦出去。确认 201 页遍历得到 10,000 个唯一消息，无遗漏／重复。

| 操作 | 样本数 | P50 | P95 |
| --- | ---: | ---: | ---: |
| 获取 100 个群 | 30 | 136.50 ms | 159.28 ms |
| 10,000 条历史中的最新 50 条 | 50 | 12.59 ms | 17.83 ms |
| 100 个群初始同步 | 10 | 140.68 ms | 156.75 ms |
| 无变化同步（不等待） | 30 | 12.05 ms | 17.13 ms |

完整历史遍历每页 P50/P95 为 30.48/50.48 ms。查询使用新增复合索引反向扫描，无 filesort；没有以不同负载下的旧数据推算生产加速倍数。历史发送者均为查看者，此数据不代表最坏未读统计负载。

100 条并发空闲 HTTP 同步请求全部在 25.06–25.37 秒返回，无提前空转或伪变化。这些是一个账号的 100 条连接，不是 100 个图形浏览器或独立用户。RSS 从 64.5 MiB 上升到峰值 116.8 MiB，完成后立即采样为 103.8 MiB；独立测试库连接数从 18 上升到 108 后回落至 18，计数包含另一个网页实验后端。

两个独立后端进程共享数据库：A 提交后 B 的 100/100 条请求各收到事件一次，提交至返回 P95 **2.309 秒**；离线期间的 3 条消息恢复后无重复。这依赖 2 秒数据库补查，不宣称跨节点毫秒级推送。

独立 SQL 回归中，1 个／100 个群的 DTO 均为 6 条查询，初始同步均为 12 条，无变化同步 100 个群为 6 条，避免按群 N+1。全局 MySQL 计数受其他进程影响，不能作为单请求精确计数。

顺序媒体测试中，后端 RSS 58.69 → 峰值 59.61 MiB；50 MiB 下载用时 40.01 秒、慢速上传 12.86 秒，均保留完整字节。这验证流式处理及超时配置，不代表并发文件容量。

## 本轮实际发现并修复

1. v12 部分入群的历史状态快照缺失成员却被标为完整，导致远端消息／启用加密事件被拒。补齐状态时修复有来源证明的快照，再清除 partial 标记；没有放宽签名或事件授权。使用全新房间完成加密复验。
2. 已在本站存在的远端房间，第二名本地用户申请入群曾仅写本地状态。改为实际完成远端 knock，申请和取消均经真实 Synapse 验证。
3. 原生房间事件缺少可靠出站投递。复用既有持久化队列，事务内记录原生 PDU，按远端并行、租约领取、有界重试；无需启用 AP 桥接。
4. 历史查询扫描及关系聚合慢，补充复合索引并拆分索引查询；维护房间级提交序号，不使用全局热点计数器。
5. 普通请求的连接截止时间截断大文件／长同步。仅放宽群媒体与同步精确路由，保留普通 JSON 限制。
6. 前端长轮询毫秒单位、初始快照与历史竞争、旧消息更新顺序、原生对话框确认遮挡，以及测试中的不完整路由／异步清理问题。
7. 状态／成员写入错误曾被内部 helper 忽略。网页群设置和邀请现在检查每步错误并回滚；五类故障注入证明事件、状态、序号与投递不会半提交，失败邀请仍可重试。
8. 联邦事务失败结果可能被远端缓存。重试改用投递租约代次作为事务编号，保持事件 ID 和 PDU 不变；避免相同失败缓存阻止恢复。队列按服务器公平分配一轮预算，防止离线服务器的旧任务占满批次、阻挡健康服务器。
9. 联邦测试服务器重用随机端口时，以固定密钥编号生成不同公钥、以固定房间本地名称创建新房间，会命中旧缓存或成员状态。测试夹具改用按新公钥派生的密钥编号和房间标识，保持正常签名校验；确定性旧密钥缓存回归及原失败用例各重复 100 次通过。
10. 既有 streaming 序列化测试造数据触发无关的异步 Feed 任务，可能在清理数据库引用后运行；仅对这些准备数据跳过模型 hooks，该包连续 20 次通过。联邦超时测试改为清理时才关闭响应，避免 EOF 与 deadline 竞争；全部原断言保留，连续 30 次通过。

## 已知限制与未覆盖项

- 当前 Element 将自定义图片 reaction 的 MXC 扩展显示为 URI 文本；普通回应、正文自定义表情和图片正常。未开放匿名私有媒体入口以规避客户端差异。
- 网页不是 E2EE 客户端。本站尚未收到远端加密状态前存在联邦传播窗口；已知加密状态后的写入、上传及重试均拒绝。
- 原先已错误清除 partial 标记、历史快照已损坏的旧实验房间不会通过猜测状态自动修复；必要时重新加入。仍处于 partial 状态的房间走修复后的补齐流程。
- 搜索是指定目录与精确解析，不覆盖 Matrix 全网；不实现 Spaces 树、外部群全文搜索或自动跟随房间升级。
- 同步最多 2,000 个活跃／邀请／申请房间，游标最多 256 KiB。超限明确提示使用原生客户端，不静默丢群；网页可继续手动刷新列表和历史。
- 对外消息成功表示本站接受，远端故障通过队列重试；超过 7 天转失败需运维核查。不能收回已下载或远端保存的文件。
- 真实浏览器为 Chromium，未在真实 iOS／Android 设备、所有屏幕阅读器、全部 Matrix 服务器／客户端版本上验证。性能与存储验证使用本地实验后端，生产 S3／代理需按部署说明复验。
- 大表索引迁移可能持锁并消耗临时空间，需评估生产副本；不支持长期混用不分配流序的旧写入实例。回退保留房间、消息、媒体和新增数据结构。

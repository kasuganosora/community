# 群组与私信异步交互审查

日期：2026-10-14。按 Emil Design Engineering 规范检查即时反馈、重复提交、取消、请求时序与失败恢复。

| Before | After | Why |
| --- | --- | --- |
| 群页接受邀请时无限轮询；状态查询失败后再次点击会重新发起加入 | 加入立即显示“加入中…”，120 秒总时限；保留 operation，重试仅查询状态 | 不让按钮永久锁定，也不重复提交已在执行的加入 |
| 切换群聊后，旧加入结果仍可能跳回原群 | 切群、换账号、卸载时取消请求和计时器；接受邀请只刷新当前群，不抢导航 | 完成后台工作不能打断用户正在浏览的页面 |
| 首次实时同步持续报错时，群历史一直处于初始加载 | 首次同步失败后单独加载可读历史，后台继续重连；同步恢复后重新对齐历史 | 单个实时接口失败不应阻断已有群的阅读 |
| 同群离开再进入后，旧历史请求可能覆盖游标；等待历史的同步结果可能跨账号落入新会话 | 房间请求版本与账号 epoch 在每个 await 后复核 | 慢响应不能覆盖当前上下文或泄露上一账号消息 |
| 群详情操作只禁用按钮，缺少实际处理中反馈；上传后可能继续写入已离开的上下文 | 保存/邀请/头像显示具体进度文案，保存与邀请按钮同步切换；上传完成后复核账号与群上下文 | 用户能判断操作被接收，迟到的上传不能写错目标 |
| 成员重试成功后仍残留旧操作错误 | 成员错误独立管理；新请求立即清除，刷新按钮显示加载中 | 错误提示必须与当前请求一致 |
| 私信已发送成功，还需等待详情与历史回读，期间 pending 已解锁、原草稿还在 | 写入成功立即完成发送并清理草稿；详情后台刷新；失败立即恢复可重试状态 | 避免“已发送却还卡住”和重复发送 |
| 已有私信历史的“重试”没有 pending；重复点击和后台轮询互相覆盖读取版本 | 手动重试独立显示“加载中…”；同一轮详情/消息读取复用请求，后台轮询不打断手动刷新或历史翻页 | 保持可读内容，避免重复请求与慢响应被后来轮询作废 |
| 删除会话/消息、离开私信的确认框请求期间无反馈 | 确认按钮显示加载状态，并在处理期间阻止重复确认 | 有副作用的提交必须给出可见反馈且只执行一次 |

## 复核后保留的已有保护

- 群成员输入：250ms 防抖、输入法组合输入隔离、请求取消、旧结果忽略、失败提示；群页与私信读取都有 API 超时。
- 群消息发送/附件：即时发送或上传进度、防重复、失败保留草稿、幂等事务重试、离开时中止上传。
- 私信附件上传和成员解析：已有同步 pending 与账号/会话代次保护；未引入额外加载动画。
- 加密群继续要求客户端；退出群不会自动重新加入。接受邀请与拒绝邀请是两个不同意图，不合并。

## 验证记录

- 群组与私信定向测试：15 个文件、79 项通过；涵盖加入总时限/重试操作、切群/换账号/卸载、同步失败后历史读取、跨账号迟到同步、私信写入与慢回读解耦、群资料重复提交及头像上传上下文。
- 两个域 ESLint、`git diff --check` 通过。
- 集成复核追加私信手动刷新：2 个文件、14 项定向测试通过（含新增 5 项）；验证即时 pending、同一读取复用、防重复、刷新失败恢复、慢翻页不被轮询打断、换账号后旧刷新不解锁新请求。追加后私信域 ESLint 与前端类型检查通过。
- 共享读取错误状态再复核：新增 2 项测试，确认“重试”复用失败操作的回读时，成功会消除旧操作错误，读取失败则保留新的读取错误；该 composable 共 12 项测试与 ESLint 通过。
- Chromium 使用真实 Vue 页面与合成 API，在 1440px 与 390px 各验证 7 项：邀请即时反馈、失败后只查询原操作、资料保存即时反馈、防重复、无横向溢出、私信待发送锁定、回读阻塞时已发送草稿立即清空。共 14 项通过，无页面异常。
- 浏览器截图：`/tmp/community-chat-feedback-browser/`；报告：同目录 `report.json`。桌面资料保存与手机加入画面已人工视觉复核。
- 浏览器使用合成账号/群组和请求拦截，没有向真实远端发送消息、邀请或更改真实资料；这不是联邦端到端投递验收。

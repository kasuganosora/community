# 发帖框布局审查（2026-10-14）

参考用户提供的 Misskey 发帖框截图，使用 [Emil Design Engineering](https://github.com/emilkowalski/skills/blob/e8a175de22ae1e49370fc144c1f3bb9aeedf988d/skills/emil-design-eng/SKILL.md) 审查共享 `PostComposer`。保留 Community 的主题颜色、正文发布接口和权限规则；共享组件同时用于首页、回复、私信草稿和发帖弹层。

| Before | After | Why |
| --- | --- | --- |
| 正文从头像旁开始，初始只有一行，功能按钮和发布按钮拥挤在底部 | 顶部放头像、可见范围和发布按钮；正文独占整行；底部放媒体、投票、CW、计数和表情 | 发布动作位置稳定，写作区域不再被头像挤窄 |
| 首页编辑区域和时间线内容边界不明显 | 使用现有浅深色令牌、细边框和圆角形成编辑卡片 | 明确输入区域，同时保持与项目其他组件一致 |
| 可见范围默认显示“公开 · 所有人可见”占据工具栏宽度 | 按钮显示“公开”等简短标签；展开后保留完整范围说明 | 日常操作紧凑，选择时仍可理解隐私含义 |
| 可见范围菜单 Escape 关闭后没有可靠的返回焦点 | 打开时聚焦当前选项，方向键/Home/End 导航，选择或 Escape 返回按钮 | 键盘用户能够完成选择，不必重新寻找操作位置 |
| 输入框主动清除了所有焦点轮廓，工具按钮 40px | 恢复正文键盘焦点边界，工具和发布按钮至少 44px | 让焦点可见，并提高手机点击容错 |
| 下拉菜单固定向左对齐且至少 256px | 对齐编辑框头部，宽度受卡片限制，长说明可换行 | 320px 窄屏也不会越出视口 |
| 手机工具栏依赖负 margin 抵消头像宽度 | 正文、工具栏各自完整占宽，分组可换行 | 减少布局耦合，较长字数计数不会挤压发布按钮 |
| 发布中仍能触发部分辅助工具 | 发布或读取源内容时禁用媒体、投票、CW 和可见范围触发按钮 | 避免请求期间改变编辑状态，保留原有上传与重复提交保护 |
| 工具按压变形没有专门遵循减少动态效果偏好 | `prefers-reduced-motion` 时移除这些变形和过渡 | 符合系统动态效果偏好；高频选择菜单不新增动画 |

## 验证

- `PostComposer.spec.ts` 和 `compose.spec.ts`：22 项通过，覆盖上传完成前禁止快捷键发布、删除重发披露、失败保留草稿、源内容不可用、表情插入以及可见范围键盘选择/提交。
- 两个修改的源码文件 ESLint 和前端 `vue-tsc -b` 检查通过。
- Chromium 使用真实 Vue 组件与 TDesign 样式，合成发布/上传接口进行 1440px 浅色/深色、390px 深色、320px 浅色以及 320px 私信深色检查。所有视口无水平溢出，工具和发布按钮均为 44px；可见范围菜单没有越界。
- 浏览器交互检查：键盘切换可见范围、Escape 恢复焦点、CW 和投票提交内容、投票/附件互斥、上传期间禁止发布、失败保留草稿、重试携带附件，均通过。
- 已人工查看桌面、窄屏与投票展开截图，确认文字、按钮和表单对齐。截图与机器报告保存在 `/tmp/community-composer-review/`，不包含真实用户内容。
- 上述浏览器检查验证组件和请求参数，不代替真实后端上传或联邦投递验收。手机首页仍使用已有发布入口打开弹层，此次未修改其入口行为。

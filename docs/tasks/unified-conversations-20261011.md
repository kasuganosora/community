# Matrix 与 ActivityPub 统一会话

目标是让网页、本站 Matrix 与外站 Matrix 用户围绕同一会话收发联邦私信，共享成员、消息关系和投递结果。保留两个协议的真实边界，不把入队称为送达，也不把服务器接收称为已读。

## 实现约束

- 网页使用 Community 登录调用 `/api/v1/chat/conversations`，Matrix 客户端使用 `/_matrix/client/v3/community/conversations`；两者调用同一服务与事务，不创建第二份消息。
- 会话成员变更有版本；接受每条消息时固定收件人快照。新成员不能看到加入前的消息，退出或封禁不会被后台重试绕过。
- 混合会话明确选择非端到端加密。既有加密房间不得静默改造、解密或转发历史。普通 Matrix 房间不因同名或客户端伪造字段变成桥接房。
- 外部 Matrix 发言必须先通过原生联邦签名和房间授权，再用明确标注完整 MXID 的本站代理 Actor 向 ActivityPub 投递。代理 Actor 没有登录用户，不冒充本站个人账号。
- 新建、发送、回复、删除、重发与重试具有稳定事务标识。编辑按删除旧消息再发送新消息实现，界面明确说明。
- 两端回复关联到真实消息；删除校验原作者并覆盖对应文字及附件事件。正文和表情只用经过校验的结构，不执行远端 HTML。
- 投递结果来自持久任务与 ActivityPub 实际投递记录，提供作者私有反馈。管理员仅查看任务元数据，不因此读取私信正文。
- 真实头像优先；公开头像合法重定向仍须逐跳安全校验，失败不能阻断消息或永久覆盖真实头像。

## 验收标准

1. 从网页或 Matrix 主动给 Misskey、Mastodon 账号发起会话，对端能收到和回复，无需先收到远端私信。
2. Community、外部 Synapse、Misskey、Mastodon 参与同一明确同意的非加密会话；非成员不能读取或发送，退出及成员变更不会扩展历史受众。
3. 回复、作者删除、删除后重发及重复事务均跨端对应；反向事件不回环、不重复，不撤回别人的内容。
4. 可复现远端失败，作者看到失败或待重试，恢复后同一任务投递成功，不产生重复帖子。
5. 富文本链接与段落、安全内容警告、图片、普通文件、音视频按双方协议实际验证。原文件字节保持与远端转码区别记录。
6. 表情回应按对端能力验证；不把 Mastodon 的收藏等同于任意自定义回应。
7. 新建、成员、发送结果及错误恢复在同一网页消息入口中可操作，移动布局与键盘交互可用。

Misskey 未写入原始 `to/cc` 的同站收件人仍无法安全推断；已知媒体地址的访问边界与正文收件权限不同；这两点不能靠扩张提及权限来掩盖。真实实测、受控协议验证和未验证范围分别记录。

## 实现与验证记录

- 会话与消息共用 Matrix 原生事件和现有 ActivityPub 持久队列，没有第二份网页聊天存储。成员协调在 MySQL / PostgreSQL 使用专用连接 advisory lock，仅串行协调过程；消息事务不持锁等待远端邀请。版本改变时保持暂停，下一次协调完成后再恢复。SQLite 仅使用进程内协调锁，不作为此能力的多进程部署后端。
- SQLite 与隔离 MySQL 核心定向回归通过；本轮未运行真实 PostgreSQL 验收。测试涵盖固定受众、移除后重新加入、新成员历史隔离、权限拒绝、请求幂等与附件编辑保留。
- 后端相关整包回归通过：Matrix Homeserver、ActivityPub、htmlsafe、models、serializer、migrate/scripts、status 与 admin API，以及根路由包。最终网页替换消息与投递锁范围调整另经定向回归通过。
- 前端完整回归 80 个测试文件 / 371 项通过，lint、类型检查、生产构建通过；后续头像样式修正另经定向检查与构建验证。
- 真实 Synapse 加入验收发现部分权限覆盖配置生成 `events:null`，已改为协议要求的对象，并验证持久化签名事件。旧错误签名历史不被篡改，真实复测使用新建房间。
- 公开头像重定向的受控 HTTPS / ActivityPub / Matrix HTTP 链路通过 51 项检查，包含真实 MXC 图片内容。环境无法访问用户截图中的 `maid.lat`，不将受控通过描述为该线上账号已验证恢复。

## 真实服务器验收

实验环境使用独立测试账号及有效实验 TLS 证书，没有关闭签名校验或放宽生产 SSRF 策略。

| 方向 / 能力 | 实际结果 |
| --- | --- |
| 本站 Matrix → Misskey / Mastodon | 主动私信、明确非加密同意、请求幂等、Direct 可见性、对端回复返回同一房间通过 |
| 外部 Synapse ↔ 混合会话 ↔ Misskey / Mastodon | 真实加入、发言、两个 AP 对端实收；AP 回复在 Synapse 房间历史中确认真实 PDU |
| 编辑及作者撤回 | 两 AP 对端旧帖删除、新 ID 重发，再撤回后远端旧对象不可访问；AP 作者删除对应 Matrix 撤回；外部 Synapse 作者撤回在两个 AP 对端均生效 |
| 回应与收藏 | Misskey 表情、Mastodon 普通 Like 收藏及 Undo 真实通过；收藏使用独立元数据，没有伪装成自定义表情 |
| 头像 | 受控 HTTPS 重定向与真实 MXC 图片内容 51 项通过；截图所示线上站点不可访问，未宣称已复现该账号 |
| 原生 Matrix / 外部 Synapse → AP 文件 | PNG、WAV、MP4、TXT 实际送达；Misskey 下载 SHA-256 与原文件相同。Mastodon 音视频经转码后可解码，原 `remote_url` 字节相同 |
| Mastodon 普通文件降级 | 修复未知 Document 的代理 404 后，正文提供同一 opaque 附件下载链接；TXT 实际下载 45 字节与原 SHA-256 相同 |
| Misskey → Matrix 多附件 | 单帖三个附件成为 audio / video / file 事件，安全提取原文件名，受保护 MXC 下载 SHA-256 全部相同 |
| 富文本及敏感内容 | Masto 真实收到安全列表、引用、链接；脚本与危险 URL 被去除。MK 内容警告不泄入纯文本正文；敏感附件为带提示的文件，无自动缩略图 |

Mastodon 的陌生人私密提及可能进入通知请求；验收检查包含过滤后的请求，没有为了通过测试修改实例策略。重复 initial `/sync` 会命中 Synapse 响应缓存；群回复复验使用真实历史 PDU / 增量同步，避免将缓存旧结果误判成消息丢失。Mastodon 媒体转码造成的 SHA 差异也不当作原字节保持。

网页真实浏览器 7 项验收通过：创建并同意非加密、发送与远端确认、回复及删除重发、刷新后的唯一新消息与旧消息墓碑、图片真实解码与编辑保留、成员增删。320px 无横向溢出，成员头像实测 32×32，悬浮发帖按钮不遮挡聊天发送。网页和聊天 API 无异常。

成员退出后的 7 项隔离检查通过：仍在群的 AP 成员收到后续消息，退出的 Synapse 用户收不到；更窄受众回复不进入广群。原生退出记录同步与重新加入的代次隔离已修复；最后真实复验确认退出后名单移除、无邀请重入被拒、显式重新邀请后可加入且使用不同成员记录。旧待发任务不可复用原成员记录的检查另由事务回归覆盖。密集实验邀请曾触发 Synapse 429，保留失败记录；后台自然重试后接受，没有修改对端限流策略。

投递故障与恢复 21 项独立检查通过：暂停实验 Synapse，令单个 QA 任务提前到最后一次重试以缩短等待，实际远端请求失败；Misskey 已实收仍不误报 Matrix 成功。作者网页显示失败、Element 专用通知房显示失败；恢复服务后网页点击重试，原 Synapse 事件只出现一次，Misskey 帖子与 status/outbox/job 数量不变，并收到一次恢复通知。外部非作者不可读取该通知。实验服务已恢复。

Element 首次进入通知房尝试旧版 `initialSync` 接口收到 404，正常同步随后显示通知；保留该兼容观察，不声称客户端控制台全程零错误。未为此放宽访问控制。

运行证据分别位于本次工作区 `/tmp/community-bridge-full-qa/`、`/tmp/community-real-avatar-qa/` 和 `/workspace/.community-unified-delivery-qa/`。每份记录保留实际测试的二进制版本，后续修补只重跑相关检查，不将早期结果冒称为每版全部重复通过。凭据与运行数据不入仓库。

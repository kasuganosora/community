# 群组布局与表单设计复查

日期：2026-10-14（Asia/Shanghai）。范围是群列表、聊天、创建/加入表单、群详情，以及这次新增的成员候选和群短地址界面。

## 设计依据

按用户指定的 [emilkowalski/skills](https://github.com/emilkowalski/skills) 中 `apple-design` 和 `emil-design-eng` 审查：应用 Apple 的层级、分组、空间一致性、动态字体与可访问性原则，以及 Emil 的输入反馈、低频动效和交互细节规范。使用已有语义颜色、字号、间距与圆角 token；没有添加 UI 或动画框架，也不把本次审查称为 Apple 官方认证。

本次实际读取 `/tmp/community-design-skills/skills/apple-design/SKILL.md` 与 `/tmp/community-design-skills/skills/emil-design-eng/SKILL.md`；以下按设计技能要求记录 Before / After / Why。

| Before | After | Why |
| --- | --- | --- |
| 群列表内容撑高 CSS Grid 的隐式最小行高。在 1440 × 960 窗口，聊天区实际高 1198px，输入框顶部位于 1039px，整个输入区落在屏外 | Grid 行使用 `minmax(0, 1fr)`，列表和滚动区域设置 `min-height: 0`。修复后列表与聊天均高 960px，输入区位于 805–960px | 最重要的阅读和发送操作应始终可见；列表与消息各自滚动，不能由数据条数决定页面高度 |
| 列表按钮高度、圆角不一致，列表与聊天背景难以区分 | 统一工具栏尺寸、次要按钮和搜索框；列表使用 grouped surface，主聊天保留主背景；选中群有色底与边框 | 通过材料层级和稳定对齐区分导航与内容，保持主操作突出 |
| 手机返回箭头是字形字符，群名、人数和详情按钮层级弱 | 使用已有返回图标，固定返回/头像/详情控件，群名允许省略，人数为次要字号 | 长群名不能挤走返回和详情操作；位置可预测 |
| 创建页标题下直接堆叠控件，选择项、输入与说明间距零散 | 名称与介绍、加入方式、邀请成员、明文确认按组排布；使用统一间距，窄屏输入至少 16px | 分组表达关系，避免 iOS 聚焦放大，小屏表单仍能逐项填写 |
| 群详情窄至 380px，长账号和短地址表单空间不足，滚动后关闭按钮消失 | 桌面抽屉扩至 420px，手机仍占可用宽度；固定抽屉标题和关闭按钮，正文独立组织；身份、资料、通知、地址、邀请与成员分段 | 减少无意义换行，滚动到任何位置仍能退出，保持清晰的编辑上下文 |
| 通知开关、成员列表和危险操作混在连续文本中 | 通知使用成组设置行；成员数量独立显示，管理操作缩进到对应成员，退出操作单独置底 | 控件与其影响对象靠近，减少误操作 |
| 输入框与工具栏分离，聚焦状态只标记文本框，附件按钮为空白 | 文本与附件/表情/提及/发送整合到一个输入面板，焦点描边只覆盖整个区域，避免父页面焦点规则造成内外双描边；补齐本地 `file-add` 图标注册 | 发送是一个完整任务；真实渲染检查能发现组件单测未覆盖的图标缺失 |
| 邀请成员必须记住完整账号 | 输入用户名或昵称显示本站候选，支持键盘选择、创建时多选，已在群内的成员不重复提示 | 降低记忆和输入负担，完整 Matrix 账号仍可手工输入 |
| 群分享地址只能复制很长的内部 ID | 有权限时可设置短地址，提供完整预览、复制入口和保存结果；旧链接保持可用 | 分享地址可读，修改的结果可预期 |
| 短地址输入与说明容易挤在一起，预览 `code` 继承全局灰底形成双层框 | 输入统一 16px/至少 44px，说明独立行，预览只保留一层背景 | 清楚区分输入与最终地址，触屏便于使用 |
| 短地址错误只在提交时出现，难以修正 | 失焦格式检查、邻近错误及 `aria-describedby`；冲突保留输入和旧地址 | 用户能定位和恢复失败，不丢失已经填写的内容 |
| 对话框缺少明确名称，触屏目标与桌面尺寸混用 | 为详情/回应对话框添加名称，保留原生焦点约束及 Escape 还焦；粗指针目标至少 44px | 键盘、读屏和触控都能理解当前位置及退出路径 |

没有新增列表进入、输入或键盘选择动画。按技能要求，这些高频操作直接响应；减少动态效果偏好保留。颜色、边框和焦点反馈使用现有主题 token，并在深浅色中实测。

## 视觉与交互证据

使用真实开发服务 `13105 → 18099` 和隔离测试数据库中的群与账号，通过 Chromium 检查以下内容；不是静态 mock 页面，也不是物理手机设备测试。

- 1440 × 960、1024 × 900、390 × 844、320 × 740，分别在深色和浅色检查聊天、详情和创建页。页面与详情没有横向溢出；聊天输入区均在视口内，长群列表独立滚动。
- 每个宽度和主题下，邀请输入搜索本站账号，方向键 + Enter 选中；Escape 关闭详情并将焦点还给“群详情”按钮。
- 390 深色群列表验证减少动态效果。上述自动浏览器记录共 33 项，无 JavaScript 错误。
- 补充 3 项控件检查：320 深色附件图标真实 SVG 渲染且可打开文件选择器；输入面板键盘焦点清楚；创建表单滚到底部后提交按钮不被底部导航遮挡。
- 已人工查看修复前桌面会话与详情截图，以及修复后桌面会话/详情、320 深色会话、390 深色创建表单，按截图修复附件空白图标。
- `GroupComposer` 与 `AppIcon` 的现有 10 项测试通过；修改文件 ESLint、`vue-tsc --noEmit -p tsconfig.app.json`、`git diff --check` 通过。整合构建与接口回归由主任务报告记录。

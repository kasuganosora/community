# 个人资料图片裁剪交互

头像和封面选图后进入编辑框，拖动调整位置，使用缩放滑块、加减按钮或键盘调整。头像按正方形导出、圆形预览，封面采用个人主页现有的 3:1 比例。

取消不上传、不替换原图；应用后上传裁剪结果到原有媒体接口，再由「保存个人资料」提交图片地址。图片仅在浏览器中编辑，没有新增上传接口或裁剪依赖。动画图片明确提示裁剪将转为静态，同时提供「使用原图」保留动画。

## 设计审查

依据 Emil design engineering skill 检查交互、触屏和键盘行为。实际检查了 1440px 和 390px 深色页面，两种图片入口。

| Before | After | Why |
| --- | --- | --- |
| 选图后直接上传，无法调整裁剪位置 | 先在模态编辑框拖动、缩放，再明确应用 | 用户可以确认最终可见区域；取消不产生上传 |
| 头像和封面没有单独的比例预览 | 头像方形裁剪配圆形遮罩，封面固定 3:1 | 预览与个人主页显示形状一致 |
| 没有触屏和键盘调整位置的途径 | Pointer capture 拖动、方向键、原生 range 控件及加减按钮 | 支持鼠标、触摸及键盘，不依赖 hover |
| 图片处理没有可返回的编辑步骤 | 原生 dialog 约束焦点；取消、Escape 关闭并返回触发控件 | 保持清晰的返回路径，避免焦点逃出弹层 |
| 动态图片裁剪可能丢失动画 | 显式提示静态导出，并可保留原图 | 不静默改变文件行为 |
| 窄屏编辑区域和操作容易溢出 | 模态框按视口限制尺寸，按钮至少 44px，内容可纵向滚动 | 390px 下操作完整可见、无横向溢出 |

## 验证范围

- 裁剪数学、图片动画检测、两种入口取消/应用、上传失败、会话变更、异步导出取消、Object URL 释放和焦点恢复；加上原有资料草稿与校验回归，共 22 项定向测试通过。
- Chromium 本地真实个人资料表单：1440px/390px 两种入口选图、取消、再次选同一图片、拖动、缩放和应用；确认取消没有上传、应用产生 PNG、头像导出正方形、封面保持 3:1（输出像素整数取整）、页面无横向溢出。
- Chromium 额外验证：带 EXIF orientation=6 的 JPEG 按旋转后的方向预览并导出（检查输出像素）；透明 PNG 输出保留 alpha=0；通过 CDP touchStart/move/end 实际触发触屏拖动，图像位置随手势改变。
- 浏览器测试使用合成图片，并拦截媒体上传响应，没有修改线上或测试账号的持久个人资料。浏览器截图、请求检查记录留在 `/tmp/community-profile-crop-qa/`。
- 文件输入维持 8 MB 限制；支持浏览器可解码的 JPG、PNG、WebP、GIF、AVIF 和 BMP。图片大于 4000 万像素或单边超过 16384 像素时明确报错。PNG 导出保留透明度，头像最长 512px，封面最长 1500px，不扩大正常尺寸的小图。
- 未在 Safari、Firefox 或实体触屏设备运行；不宣称这些浏览器已经完成验收。

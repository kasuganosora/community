# Community → Misskey 转发修复

日期：2026-10-11。基线为 `ea6d497`，使用保留的真实 Misskey 2026.10.0 实验服务、既有账号和已接受关注关系。未运行长时间压测。

## 原因与修复

Community 的 `Announce.published` 使用 `RFC3339` 格式化，丢失小数秒；原始 Note 保留小数秒。原帖发布后同一秒内转发，转发时间可能被截断到早于原帖。Misskey 的 `ApInboxService.announceNote` 会拒绝这种活动，记录 `skip: malformed createdAt`。HTTP 投递成功不代表异步接收端已经保存转发。

真实修前例子：原帖时间 `2026-10-11T04:12:26.679Z`，转发实际创建于该秒的 `.742`，但发出的转发时间为 `2026-10-11T04:12:26Z`。自己的帖子和另一位 Community 用户的帖子均复现，较早的远端原帖转发正常；新事件不存在历史队列阻塞。

修复使用 UTC `RFC3339Nano` 保留实际转发时间。Undo 内嵌 Announce 同样保留精度，不修改活动 ID 或原帖 URI。

排查中另外修复发送前对原帖的权限复核：原帖被删除、改为私密、设为仅本站或定时，或原作者屏蔽收件人后，不能继续发送已排队的 Announce；对象 URI 也须与当前引用一致。撤销活动仍可发送。该权限缺口不是本次公开转发丢失的根因，合法公开转发在修前也能通过原有授权检查。

# 设置、后台与数据迁移的异步反馈审查

日期：2026-10-14。按 Emil Design Engineering 的即时反馈原则检查读取、保存、删除、刷新和账号/页面切换；保留已有布局，不增加解释性说明。

| Before | After | Why |
| --- | --- | --- |
| 内容过滤、域名屏蔽加载失败，同时显示“还没有” | 读取中、失败重试、成功空态互斥 | 请求失败不能冒充数据为空 |
| 授权应用撤销、通行密钥/过滤器/屏蔽域名删除，点击后按钮不变 | 在请求前标记当前操作、显示处理中并防重复；成功后更新列表，失败仍可重试 | 慢请求必须立即回应操作 |
| 通行密钥等待浏览器后，可能继续用新会话提交；个人资料保存的旧响应可覆盖新账号 | 设置域复用会话/组件作用域检查；多步操作逐步确认身份，资料保存同时校验账号 ID | 账号切换后丢弃旧结果及后续步骤 |
| 头像挂件尚未读完，只显示“不使用”，无重试 | 加载状态、失败重试；选项就绪后才可保存 | 避免用不完整表单误操作 |
| 后台广告/挂件没有读取反馈，切换分类沿用上个分类的数据 | 即时加载、重试、请求版本保护；分类变化重置编辑并读取新列表 | 共享页面的参数变化必须更新内容 |
| 后台角色成员请求未完成，先显示“暂无成员 / 共 0 人” | 独立成员 loading、错误重试；最新角色请求才能更新列表 | 不将旧角色结果或未加载状态当成新角色数据 |
| 多个后台列表在报错后仍显示空数据 | 账号、举报、公告、审计、远端实例、邀请、队列、发现规则和 Webhook 空态均排除错误状态 | 统一空态语义 |
| Webhook 初始请求只禁用控件，没有可见等待状态，计数显示 0 | 显示处理状态；请求中或失败不显示伪计数 | 明确接受了操作 |
| 导入任务初始读取、手动刷新无反馈；切换任务后旧刷新失败覆盖当前页面 | 独立列表/任务刷新状态、防重复、请求版本检查；失败不显示“暂无任务” | 允许在正确位置等待和重试，不重复提交导入 |
| 私有备份加载失败也显示“暂无私有备份内容” | 失败保留错误及刷新入口，隐藏空态 | 避免误认为数据丢失 |

## 覆盖与边界

- 设置：个人资料（含现有裁剪/上传）、密码、通行密钥、已授权应用、头像挂件、过滤器、域名屏蔽；资料已有缓存和用户草稿保护继续保留。
- 后台：审查设置中心、安全/规则、系统状态、概览，以及上述列表的读取/空态；设置中心原有 generation、保存反馈、错误重试已完整，未重新实现。后台角色、广告/挂件针对实际缺失补充请求隔离；未声称所有后台业务都进行了故障注入。
- 数据迁移：个人/整站共用页面、任务列表与任务进度、私有备份；保留原有导入确认、服务器任务恢复和账号清理。
- 没有调用真实保存、发布、删改、导入 API；回归使用可控制完成/失败顺序的模拟请求。全局路由等待和搜索交互由并行任务处理，不在本文的实现范围内。

## 验收

- 延迟请求期间立即显示正在处理/禁用重复动作，不出现假空列表。
- 失败显示错误，读取可重试，保存失败保留表单，删除失败保留原项目。
- 在会话切换、组件卸载、广告/挂件分类切换和角色/导入任务切换后，旧响应不得覆盖新页面。

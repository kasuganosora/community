# 账号备份与同域名整站迁移

Community 提供两种入口：管理员将 Misskey / Mastodon 换成 Community，以及用户将已有备份导入自己的账号。两种入口的权限、身份和数据处理方式不同。

整站迁移要求继续控制**原站域名和原账号地址**。导入会保留源 Actor / 对象 URI、密钥 ID 和公私钥，不要求每个用户执行 Move 或重新关注。它不会替你切换 DNS、停止源站或将两个站点变成可同时写入的副本。

当前账号域名必须与目标网页域名一致。Mastodon 中 `LOCAL_DOMAIN` 与网页域名不同的部署会被预检阻止，不能将其静默改成新的账号地址。

“保留原始数据”和“转换成可继续使用的功能”是两件事：支持的字段进入正常业务表；尚无等价实现的数据进入私有归档，并在报告中提示。涉及身份、登录或可见性降级的情况会阻止执行。不能把一份带警告的报告当作所有源站功能完全等价的证明。

## 管理员整站迁移

网页入口为「设置 → 整站迁移」。仅当前仍具有管理员权限的本地账号可上传和执行任务。整站包包括凭据和私钥，普通用户的导入入口拒绝这种包。

支持的数据库适配器：

| 来源 | 导出方式 | 验证版本 |
| --- | --- | --- |
| Misskey | `scripts/migration/export_misskey.py`：PostgreSQL 分页只读读取（可续传）+ 本地媒体快照或对象存储 | 2026.10.0 |
| Mastodon | `scripts/migration/export_mastodon_db.py`（直接读数据库，向导使用）或原站 Rails runner `export_mastodon.rb` | 4.7.3 |

整站迁移始终是两步：**先用导出器生成 `bundle.json` 和媒体，再用 `community-transfer`（或网页「整站迁移」）预检并导入。** `tootctl` 没有一步完成整站导入的命令；`tootctl` 只负责实例设置（`tootctl admin import-misskey-meta`）和 passkey（`tootctl passkeys import-misskey`）等附属步骤。安装向导的「从 Misskey / Mastodon 迁移」会按顺序自动执行这些步骤。

**导出范围：** 默认只导出本站相关数据——本地用户及其资料、密钥、帖子、文件、关注/拉黑/静音、列表、书签、投票、聊天等，以及这些数据引用到的远端实体（关注关系两端的远端账号、本地帖子回复/引用/转发的远端帖子、远端对本地帖子的回复、本地帖子收到的表情回应及其用户、相关文件和表情）。源站缓存的其余远端内容（通常占数据库的绝大部分）不会被读取；指向导出范围之外的引用会从规范字段中去掉并以 `remote_reference_trimmed` 提示，原始值仍保存在私有归档中。需要完整导出时加 `--include-remote-cache`。

导出器按主键分页读取（每页一个短的只读事务，连接设置 `default_transaction_read_only=on`），进度按表写入状态目录（默认 `<output>.state`），中断后重跑同一命令会从检查点继续；内存占用有上限，不随源库大小增长。运行中每隔几秒在 stderr 打印 `progress stage=notes done=…/… eta=…`。失败时打印所在阶段和原因（密码会被遮蔽），`--verbose` 打印完整调用栈。对仍在运行的源站可用两阶段方式：源站在线时 `--fetch-only` 做全量读取（可用 `--max-rows-per-sec` 限速），停止写入后运行 `--final-sync` 补齐新增、更新和删除的行并生成迁移包。

详见 [Misskey 导出器](../scripts/migration/README-misskey.md)（含只读数据库角色的 SQL 和 SSH 隧道示例）和 [Mastodon 导出器](../scripts/migration/export-mastodon.md)。Mastodon 需要源站自己的加密配置来读取现代版本中加密保存的密钥；单独复制一个数据库文件并不一定足够。不要将 SQL dump 当作用户备份上传，先使用适配器生成 `bundle.json` 和媒体文件。

当前转换范围包括：

- 用户资料、资料字段、头像与封面、账号可见性设置、系统账号，以及受支持的管理员标记。
- 原密码校验数据和原联邦签名密钥。兼容的 bcrypt 密码无需用户重设；后续修改密码使用 Community 的本地格式。没有邮箱的源账号仍可用用户名登录。
- 原帖、回复、转发、内容警告、明确收件人的私信及会话、本地专用内容、附件与受支持的投票数据。
- 关注及待审批关注、拉黑、静音及其期限、域名屏蔽、列表、书签、喜欢、自定义表情和表情回应。
- 源数据库原始记录的私有归档，用来保留未映射字段和审计来源。

导入时不重放历史帖子的 Create、历史点赞或通知。本站专用聊天保留为本站内容，不能借迁移变成可向联邦公开的帖子。普通密码登录和签名密钥的保留，不代表旧登录会话、OAuth 令牌、安全密钥、外部认证或源站所有角色权限可以直接使用。

预检会检查同域身份、重复账号、密钥匹配、密码格式、媒体路径/大小/校验和、引用完整性和私信收件人等。启用的未支持 MFA、依赖 password pepper 的凭据、无法保持的隐藏策略等不能静默降级。Misskey 的某些频道、引用、群聊策略，以及其他无等价实现的内容可能只能归档；必须逐项查看报告。

### 推荐切换流程

1. 在隔离的 Community 数据库上演练，保留原站数据库、媒体和加密配置的可恢复备份。
2. 先读源站适配器说明并导出（见下方命令行）。正式最终导出应在源站停写后进行（或停写后运行 `--final-sync`）；只读读取不能冻结外部文件变化。
3. 将目标 `APP_BASE_URL` 配成原站的完整地址。在隔离网络或本机映射中验证，避免提前把生产请求切到未完成的目标。
4. 上传私有迁移包，等待预检，审阅计数、警告和阻断项；解决阻断项后生成最终包。
5. 执行经过预检的版本，检查原密码、原 Actor / 公钥、关注者及私信权限、附件实际下载、旧对象和媒体链接。检查报告中的创建、跳过和归档计数。
6. 完成源站停写和最终快照后，再切换反向代理 / DNS。确保只有一套软件继续接收写入，保留回滚所需的源数据。

相同包的重复执行利用导入凭据去重；同一源记录内容发生变化会报告冲突，不把新的源快照自动覆盖到已导入记录。演练建议使用独立数据库，最终导入使用最终快照。

### 命令行

命令行和网页共用预检、事务及去重逻辑。工作目录决定目标 `uploads/media`；配置文件使用目标 Community 的数据库和加密配置。

第一步，在能连到源数据库的机器上导出（以 Misskey 为例；连接参数用 `PG*` 环境变量和权限为 0600 的 `PGPASSFILE`，或不含密码的 `--dsn`）：

```sh
python3 scripts/migration/export_misskey.py \
  --base-url https://your-misskey.example --source-version 2026.10.0 --id-method aidx \
  --source-dir /private/misskey-files \
  --output /private/final-site-bundle
# 媒体在对象存储中时改用 --object-storage-mode reference|copy（见导出器说明）
# 需要导出全部远端缓存时追加 --include-remote-cache
```

退出码 `0` 表示已生成，`2` 表示已生成但有阻断项，`1` 表示失败（重跑可续传）。

第二步，用目标实例配置预检并导入：

```sh
go build -o community-transfer ./cmd/community-transfer

# 预检不导入账号数据，但会执行目标数据库的结构升级。
ENV_FILE=/private/community.env ./community-transfer \
  --scope site --input /private/final-site-bundle \
  --report /private/preflight.json

# 使用另一个未存在的报告文件；不要覆盖预检证据。
ENV_FILE=/private/community.env ./community-transfer \
  --scope site --input /private/final-site-bundle --apply \
  --report /private/import-result.json
```

退出码 `0` 表示完成当前操作，`2` 表示预检阻止执行，`1` 表示读取、运行或报告写入失败。预检成功不等于已经执行导入。命令行默认 `--max-records 100000`、单个 JSON 64 MiB；较大的整站包需提高 `--max-records`、`--max-json-bytes` 和 `--max-expanded-bytes`（`bundle.json` 会整体载入内存，请预留内存）。

网页接受 ZIP、tar.gz 或适用的 JSON / CSV。整站目录打包时让 `bundle.json` 和 `media/` 位于归档根目录。命令行也接受目录，并先建立私有快照；不要对正在变化的目录运行导入。

## 用户个人备份

入口为「设置 → 数据导入与导出」。可下载 Community ZIP 备份，或选择来源和类型上传已有文件：

| 来源 | 支持的文件 |
| --- | --- |
| Community | 本站导出的 ZIP，含规范数据和可导出的媒体 |
| Mastodon | 官方个人数据归档（ZIP / tar.gz），以及受支持的 CSV 集合 |
| Misskey | Notes JSON；关注、拉黑、静音、列表等分别导出的 CSV |

源站导出文件本身缺少的内容无法凭空恢复。例如 Misskey Notes JSON 不包含账号密码、完整资料和整站聊天库，Mastodon 个人归档也不是整站数据库备份。按文件实际包含的数据预检。

个人导入只修改登录用户可控制的数据，不接管源账号的联邦身份，不接受密码或私钥，也不提升管理员权限。远端账号引用通过真实发现或已知本地记录核实，不能猜测 Actor 地址。导入的出站关注按正常关注流程处理；无法证明的远端关系不会被伪造成已获批准。

本人发出的可转换帖子进入当前账号；收到的私信和无法安全恢复的内容保存在「仅自己可见的导入归档」，不会冒充原作者重新发布。归档可分页阅读正文并主动查看可用附件。其他用户、只有资料读取 scope 的令牌以及跨账号请求不能读取这些备份或归档。整站原始记录中的密钥等敏感内容不在个人归档接口或个人导出中返回。

仅有 Notes / CSV、没有源站地址的备份使用文件内容区分导入来源；同一文件可去重，但来自不同且内容重叠的文件不保证逐项合并。报告会提示这一限制。

## 执行、安全和资源

上传后后台预检生成版本标识，执行必须提交同一个版本。一个包的业务写入在同一数据库事务中完成，失败回滚；任务租约和记录凭据用于重试与重启恢复。已完成任务再次执行不会重复创建帖子。上传包删除不会撤销已导入的数据。

后台同时处理最多两个任务。网页默认限制为压缩输入 256 MiB、展开后 1 GiB、单文件 128 MiB、单 JSON 64 MiB、20,000 个文件及 100,000 条规范记录。命令行可通过 `--max-expanded-bytes`、`--max-files`、`--max-records` 和 `--max-json-bytes` 提高上限。导出器以流式方式运行、内存有上限；导入器仍会把 `bundle.json` 整体解析到内存，超大实例应使用默认的本站范围导出，并按包大小预留内存。

提交后会清理受影响的时间线缓存，且不发送历史事件。缓存清理失败会在已成功导入的报告中明确警告，可重复导入触发清理。此协调覆盖当前进程；多实例部署应在维护窗口完成导入与缓存重建，避免另一进程在切换时写回旧缓存。

应为上传包、展开快照、待提交媒体和数据库预留空间。媒体在提交前复制，事务失败会清理本次复制；进程被强制终止可能留下私有临时文件，清理前确认没有任务使用。上传 / 导出请求预算为 5 分钟，后台单次处理预算为 30 分钟。

默认任务目录为工作目录下 `.data-transfers/`，可用 `DATA_TRANSFER_DIR` 指定持久目录。目录权限为 `0700`，私有文件为 `0600`。部署时持久保存该目录、数据库和上传目录，限制运维读取权限；迁移包包含私钥、凭据和私信，不要上传到公共对象存储、提交到 Git 或写入普通日志。

仓库 Compose 配置使用 `transfer-data` 卷持久保存任务包，Docker 构建上下文排除本地 `.data-transfers/`。运行镜像同时包含 `/app/community-transfer`；需要命令行导入时，将私有源包只读挂载到容器中并使用目标实例配置。

导入保留本地文件的真实字节和校验和；源站本来未缓存的远端附件只保留明确标注的远端引用，不能将其报告为已备份文件。源站位于同域 `/files/` 或 `/system/` 的受支持旧文件链接通过精确映射转到导入媒体。其他 CDN 域名需要保留原存储和路由，不能仅靠应用接管另一个域名。

Community 个人导出遇到已声明的本地媒体文件缺失会失败，不生成看似成功却缺少文件的备份。导入的 HTML、SVG 等附件只允许下载；常用图片和音视频可内联展示。

整站包、私有数据库归档和个人备份都不能替代部署级数据库 / 媒体备份。最终切换前，保留并验证可恢复的原站备份。

## 实际验证范围（2026-10-03）

使用保留原域名配置的独立 Community / MySQL 目标验证，未切换原 Misskey / Mastodon 的 DNS 或写入源数据库。

| 来源 | 实际导入数据 | 核对内容 |
| --- | --- | --- |
| Misskey 2026.10.0 | 30 个账号（17 个本地，含 3 个系统账号）、14 份凭据、17 对本地密钥、154 帖、71 份实际文件及 10 个远端引用 | 原密码登录、旧 Actor URI / keyId / 公钥、原密钥签名、全部文件 SHA-256、资料表情、关注活动 ID、私信权限；64 条私信按源线程及精确参与人组成 45 个会话，19 条同组回复复用会话 |
| Mastodon 4.7.3 | 7 个账号（4 个本地，含实例 Actor）、3 份凭据、4 对本地密钥、89 帖、145 份实际文件及 4 个远端引用 | 原密码、原密钥、`/actor` 与旧数值 Actor 路径、145 个旧媒体链接、资料表情、28 条私信的收件权限、关注活动 ID |

两种导入均检查了重复执行没有新增记录 / 文件、没有重放历史联邦活动。真实 MySQL 两个并发导入任务只产生一份帖子和媒体；租约取消 / 恢复及旧表结构升级有独立回归。未支持 MFA、隐藏策略和账号生命周期状态的负向包被预检阻止。

真实 Chromium 页面验证了个人导出、上传、异步预检 / 执行、重复导入、管理员整站重导、跨账号隔离及 Misskey Notes 自动识别。Community 原生 ZIP 在两个账号间往返后，24 条收到的私有消息及 PNG 附件正文、内容警告和字节一致；缺少本地文件时导出明确失败。

最终 Go 回归通过 73 个包、6,731 项测试及子测试，44 项环境相关检查跳过；新增 MySQL 专项另外在真实数据库执行通过。前端 148 项测试、lint、类型检查和生产构建通过；源适配器 Python 13 项、Ruby 6 项 / 29 个断言通过。Compose 配置已校验。这些结果覆盖上述版本和数据，不构成对所有源版本、超大数据规模或完整协议的认证。

# 推荐与热门话题

Community 的首页发现页使用独立的推荐接口，关注时间线继续按原有规则分页。推荐不是全网爬虫，只使用本站已取得、当前允许主动推荐的内容。实现依据见[研究与实施计划](tasks/community-recommendation-research.md)，隐私验收见[独立验收记录](tasks/recommendation-privacy-acceptance.md)。

## 启用与回退

升级时自动创建推荐反馈表、远端作者发现许可字段和审计详情字段。首次部署推荐默认关闭；在 **管理后台 → 内容发现** 查看运行状态，在 **性能设置** 开启推荐时间线与关注建议。热门话题有独立开关。

- `config.recommendation.enabled`：推荐总开关，默认 `false`。关闭后首页落到关注页、账号建议为空，旧推荐游标不能继续使用。
- `config.recommendation.mode`：`auto` 或 `rules`，默认 `auto`。`rules` 使用公开热度、新鲜度和探索规则；允许个性化时加入明确兴趣和合格的公开关系信号。
- `config.recommendation.meili_approved_version`：已审核的增强索引版本，默认空。**安装 Meilisearch 不等于证明推荐质量提高**；未完成对应版本的质量评估时继续使用规则模式。
- `config.discovery.trends_enabled`：热点开关，默认 `true`，不随个人退出推荐而关闭。

设置事务同时保存推荐策略版本，跨 API 副本直接读主库。关闭后再开启、改变算法模式或撤销增强审批都不会让旧窗口重新生效。管理员可独立禁止推荐作者、帖子或话题，填写原因并撤销；这些操作保留审计，不删除帖子或封禁账号。

用户在 **设置 → 内容发现** 选择关闭、公开发现或个性化，并可明确选择阅读语言。空语言列表表示不限制；未知语言内容不会被错误判断为不匹配。发表内容的语言默认值不充当阅读偏好。作者的“允许推荐账号”和“允许索引公开帖子”是另一组独立设置。

## 数据流与限制

SQL 是资格的最终依据，Redis 只存候选和短期顺序。规则/Meili 候选合并后最多 400 个，冻结最多 200 个位置，按 20 个位置组成逻辑块；每块同作者最多 2 条、同一远端实例最多 8 条，并在候选充足时保留 4 个探索位置。过滤会产生短页，客户端按返回游标继续，不以短页判断结束。

每账号最多 2 个推荐窗口，固定 10 分钟有效期；部署默认最多 512 个窗口，64 MiB 缓存预算。候选池每 2 分钟更新、最多使用 5 分钟，根帖窗口为最近 7 天。游标绑定账号、偏好修订、部署策略、窗口和位置，并使用部署密钥派生的专用 HMAC 密钥签名。

每页重新检查当前可见性、作者收录许可、封禁/屏蔽/静音、个人及站级排除和 hide/warn 过滤。引用对象同样检查；嵌入对象不合格时整卡不进入推荐。远端作者必须明确允许发现，且许可检查不超过 24 小时；缺失或失效不会自动当作允许。后台有限刷新 Actor，收到一条新帖不会延长旧许可。

不读取私信、Matrix 聊天或书签构建画像，不收集逐帖曝光和停留时长。通用模式不按本人的关注或互动进行排序，必要的隐私过滤仍会读取屏蔽等关系。用户排除规则不验证任意帖子 ID 的存在性，避免通过成功/失败差异探测私信。

Redis 不可用时新请求只返回一页经过相同资格检查的时间顺序回退，响应标记 `chronological_fallback`；旧游标要求刷新。SQL 资格检查失败返回不可用，不放行旧缓存。最终 HTTP 响应使用 `Cache-Control: no-store`。

## Meilisearch 增强

复用现有 `MEILISEARCH_ENABLED`、`MEILISEARCH_HOST`、`MEILISEARCH_API_KEY` 和索引前缀配置。推荐使用独立、不可变代次索引；只写合格的最近 7 天公开原帖，并等待设置/文档任务成功后发布。查询只在后台产生共享兴趣候选，前台翻页不调用搜索引擎。

增强版本包含服务端版本、推荐 schema 和模型配置；只有当前版本与管理员审核版本精确一致、索引就绪且数据未过期才使用增强候选。失租的构建者不能发布，后台保留最多两个管理中的索引并回收失败代次。词法查询不发送 `hybrid` 参数。

模型版本、模型配置或搜索端点变化还会使旧候选池和分页窗口失效，不会因为后台仍保存原来的审核值而继续返回旧增强结果。后台将有效索引与最近的构建／查询异常分开显示；异常在共享 Redis 中按部署配置记录，对应操作成功后清除，失去租约的任务不能覆盖新状态。

语义混合还要求显式部署 `RECOMMENDATION_EMBEDDER_NAME`、`RECOMMENDATION_EMBEDDER_MODEL_VERSION`、`RECOMMENDATION_EMBEDDER_CONFIG`，以及 `RECOMMENDATION_EMBEDDER_BUDGET_APPROVED=true`、有效的 `RECOMMENDATION_EMBEDDER_MAX_DOCUMENTS` 和 `RECOMMENDATION_EMBEDDER_MAX_UNITS_PER_HOUR`。小时预算为部署共享，提交一个文档或查询分别消耗一个单位，失败也不退回；它是工作量上限，不是模型收费的精确计量。不会自动安装或下载模型。模型配置可能含凭据，应按部署机密管理，后台诊断不返回原始配置。

本版构建预算：SQL 扫描最多 5,000 个公开根帖；提取前检查原始正文、引用和标签预算，单条正文/CW 上限 64 KiB，最多 16 个标签，原文字节和最终 JSON 文档分别限 16 MiB；这些不是进程 RSS 上限。总构建 70 秒、任务等待最多 60 秒。每兴趣桶查询总预算 1 秒，部署最多 2 个并发搜索槽。`RECOMMENDATION_MEILI_DATABASE_MAX_BYTES` 默认 512 MiB，按整个 Meilisearch 的数据库大小预留 64 MiB 才允许构建；它是准入检查，不是远端磁盘硬配额。超预算或构建失败保留规则模式，不能把部分索引宣称为全量完成。

## 热点与兼容接口

`GET /api/v1/discovery/tags` 支持 `window=24h|7d`、`scope=local|federated`、`limit` 和签名游标。federated 表示本站已知的本地加远端内容，不代表整个联邦。帖子数及不同作者数是窗口内当前合格内容的精确计数；不足 5 位作者时标为近期话题 `kind=recent`，不伪装成热门榜。

增长比较最近 6 小时与前 6 小时，没有基数时明确标识；不从零值推断完整的新入榜历史。每次聚合最多 5,000 个原帖、50,000 个标签关联；每进程同时执行最多 2 次，另有 16 个等待位置，排队与查询共用 3 秒期限。超过预算返回不可用，不返回标称精确的部分榜。候选缓存最多 200 个话题，读取旧页仍重新验证当前资格。

旧 `/api/v1/trends/*` 保留兼容形状；标签 history 使用 UTC 日历日，而非把滚动 24 小时写进当天计数。建议账号 v1 返回 `Account[]`，v2 返回 `Suggestion[]`；网页使用 v2。公开趋势接受可选认证，无效凭据会拒绝，不会降为匿名请求。

## 网页接口与运维

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/discovery/statuses` | 登录后的推荐窗口，最多 20 条；游标失效返回 `reset_required` |
| `GET/PUT /api/v1/discovery/preferences` | 三态偏好、阅读语言与修订号 |
| `GET/POST /api/v1/discovery/feedback` | 列出/写入本人的排除规则 |
| `DELETE /api/v1/discovery/feedback/:id` | 撤销本人规则；不能操作他人或站级规则 |
| `GET /api/v1/discovery/tags` | 滚动窗口话题列表 |
| `GET /api/v1/admin/discovery/status` | 非敏感索引、候选池、租约、缓存预算诊断 |
| `GET/POST/DELETE /api/v1/admin/discovery/feedback[/:id]` | 需要设置管理权限的站级停推及审计 |

Prometheus 指标前缀 `community_discovery_feed_`，包括请求结果、服务耗时、池规模、截断和刷新结果。缓存保留字节是保守准入预算，不冒充 Redis 实际内存计量。

生产开放前应使用本站人工相关性样本评估规则/增强模式，并按研究计划检查分组效果和时延。本版没有可靠曝光数据，不报告点击率提升。曝光采集、训练模型和公开 Matrix 群推荐不在本次范围内。

补充的 Meili 能力、隐私、跨副本、质量与模型验收见[专项验收记录](tasks/meili-acceptance-20261014.md)。其中明确区分实际引擎验证、受控标注集结果和网络阻塞的真实语义模型检查；不能仅因测试套件通过就批准生产增强版本。

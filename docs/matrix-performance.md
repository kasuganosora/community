# Matrix 性能与可靠性验证

本报告记录 2026-10-03 的独立实验。比较对象为 `9e47c2a` 的服务端与本次修改，固定读取使用同一份规范 v10 事件数据。性能测量版本完成 18 个读取场景、6,060 次请求，全部通过内容一致性检查；另验证消息发送、设备消息确认及真实客户端交互。

基线二进制 SHA-256 为 `a73c68e89de3e398e7984c05bdd90eb1434b8ad3455c754b279e475f25611cd2`，性能测量版本为 `e37719b0aea28e3881a67bb6718c32b905d9e3776f94c30e1699ca40e65ea05d`，固定数据清单摘要为 `1aad7cde7eafb26f404a2e42508a51411bb35c1baa7ba4cb6ed5e204332796ee`。性能测量完成后，真实 Element 复验发现认证缩略图的跨域资源策略阻止图片预览，补充修复了该响应头。交付二进制 SHA-256 为 `8b1962dae4b7de6d1d94229aaa46490d6c43ab3447c090ff2ddaff3d2d15303b`；下列性能数据来自前述 `e37719b` 版本。交付版另进行完整后端、协议和真实客户端回归，不将此前测量归为重新压测的结果。

## 测量方法

实验使用独立 MySQL 数据库、Redis DB 14 和本机 8091 端口，与日常开发及联邦实验的数据隔离。初始种子包含 30 个账号、100 个房间、50,000 条时间线事件，连同状态和成员事件共 51,843 条。事件具有合法 PDU、事件 ID 和事件发生前的状态快照。两个固定读取账号分别加入 2 个、61 个房间；发送、回执和设备消息使用另外的账号及房间。

服务端两版均使用 `GOMAXPROCS=2`、生产日志级别、100 个数据库最大连接和 10 个空闲连接。机器总 CPU 配额为 4 核。测量期间暂停其他构建、浏览器及压测任务。两版使用相同查询、完整游标和数据，记录响应结构、事件数量及归一化摘要；摘要仅排除游标和事件年龄，不能替代权限与分页验证。

2 房间账号的首次同步、空增量同步、有变更增量同步、历史首页和深分页，各运行并发 1 / 8 / 32、持续 3 秒的闭环请求。61 房间账号的三类同步各采集 3 次串行请求，只报告中位观察值。时间线和历史页大小均为 20。HTTP 延迟包含完整响应读取，解析和校验耗时计入墙钟时间与吞吐；同时记录客户端 CPU，避免误把压测器瓶颈当成服务端上限。

SQL 指标读取隔离数据库连接的 `performance_schema` prepared Execute 计数、扫描行数和数据库计时，不重置全局计数。计数可能包含同库后台工作，也包括同步引起的写入。轻量场景各采样 3 次，多房间场景各采样 1 次。

`/sync` 虽然使用 GET，仍会更新在线状态、投递和确认设备消息。复测必须使用专用账号与设备，保存完整的不透明 `next_batch`，不要拿日常加密会话测试。通用脚本及参数见 [Matrix 压测说明](../scripts/benchmark-matrix.md)。

## 性能结果

基线为 1,420 次请求，性能测量版本为 6,060 次请求；18 个固定读取场景均无 HTTP 或语义校验错误，逐场景的事件数量、房间数量和归一化内容摘要一致。该数字不表示旧版协议没有缺陷：私有回执泄漏在独立账号中复现，候选修复后通过检查。

2 房间账号，并发 32，每个场景持续 3 秒：

| 场景 | 基线 p95 | 优化后 p95 | 延迟变化 | 基线 → 优化后 RPS |
| --- | ---: | ---: | ---: | ---: |
| 首次同步 | 2,461 ms | 573 ms | -76.7% | 14.9 → 68.7 |
| 空增量同步 | 822 ms | 373 ms | -54.6% | 48.9 → 133.8 |
| 有变更增量同步 | 1,181 ms | 1,064 ms | -10.0% | 33.0 → 41.2 |
| 历史首页 | 1,152 ms | 183 ms | -84.2% | 44.7 → 280.6 |
| 历史深分页 | 994 ms | 178 ms | -82.1% | 43.5 → 275.8 |

61 房间账号，每个场景仅 3 次串行请求：

| 场景 | 基线中位数 | 优化后中位数 | 延迟变化 |
| --- | ---: | ---: | ---: |
| 首次同步 | 5,137 ms | 1,830 ms | -64.4% |
| 空增量同步 | 2,585 ms | 34.7 ms | -98.7% |
| 有变更同步 | 3,176 ms | 1,999 ms | -37.1% |

对应 SQL 采样：

| 场景 | SQL Execute / 请求，前 → 后 | 扫描行 / 请求，前 → 后 |
| --- | ---: | ---: |
| 61 房间首次同步 | 2,690 → 874 | 704,006 → 73,284 |
| 61 房间空增量同步 | 1,342 → 32 | 104,120 → 3,743 |
| 61 房间有变更同步 | 1,527 → 950 | 236,727 → 139,662 |
| 单房间历史页 | 23 → 5 | 10,984 → 558 |

有变更的大账号同步仍有明显的逐房间数据库开销，不能将空增量的提升比例套用到所有同步请求。

### 有界发送与媒体

普通消息和不透明加密事件各在并发 1 / 8 / 32 下发送 50 条，共 300 条。两版均返回 300 个唯一事件 ID，收件人历史中每个 ID 恰好出现一次，类型、发送者和内容一致。

| 发送类型 | 并发 | 基线 p95 | 性能测量版本 p95 |
| --- | ---: | ---: | ---: |
| 普通消息 | 1 | 47.1 ms | 40.3 ms |
| 普通消息 | 8 | 172.0 ms | 228.6 ms |
| 普通消息 | 32 | 673.7 ms | 966.3 ms |
| 不透明加密事件 | 1 | 52.5 ms | 52.2 ms |
| 不透明加密事件 | 8 | 193.0 ms | 190.0 ms |
| 不透明加密事件 | 32 | 833.4 ms | 788.3 ms |

发送没有全场景提速。最终发送前，每个写入房间已比基线开始时多 300 条前轮测试消息及少量协议探测事件，未删除或复位历史，因此这部分不具备固定读取的等量数据条件。普通消息并发 8 / 32 的 p95 分别上升 32.9% / 43.4%；保留该结果，不能仅凭这些有限样本归因于代码或声称发送容量提高。

4 个媒体样本的重复下载均保持 SHA-256，一律拒绝匿名访问认证下载接口。每项 5 次请求，1 MiB 本地下载中位数为 3.69 → 4.15 ms，图片缩略图为 1.62 → 1.66 ms；这些小样本没有证明本地下载延迟降低。联邦连接复用和解析内存开销另由定向测试及微基准验证。

## 优化与正确性约束

- **同步读取**：批量读取状态和撤回元数据，合并未读计数及线程回执查询，只读取需要的列；通过事件、账户数据、回执、成员发布时间和输入状态筛选有变化的房间，跳过无变化房间的构建。同一成员共享多个房间时，设备会话查询按用户去重后批量执行。缓存只在单个请求内复用，避免跨账号或成员变化后沿用权限结果；全局在线状态和设备列表仍使用完整成员范围。
- **事件与历史分页**：批量加载成员和撤回信息，提前命中设备范围内的发送事务重试；历史读取按事件发生时的状态判断权限，过滤不可见事件后继续补页，使用时间戳与事件 ID 共同定位分页边界。
- **设备消息确认**：将待确认消息 ID 按账号、设备持久化为最多 100 条的一批，只有客户端提交相应完整同步游标才确认这批消息。同一游标重试可重获未确认内容，新到达消息不会被旧确认删除。新增表由启动迁移创建，保留原设备消息中的载荷。
- **长轮询与取消**：请求结束时释放自己的通知等待者；取消传到数据库和媒体 HTTP 请求。真实处理器回归中，旧实现三批请求累计遗留 20 / 40 / 60 个等待者，修复后均为 0。
- **私有回执**：`m.read.private` 仅返回给所有者，不通知其他账号，也不经联邦发布；仍参与自己的未读位置计算。
- **媒体**：复用 Homeserver 自己的受保护联邦 HTTP 连接池，直接解析有大小限制的 multipart 响应，图片上传省去未使用的 BlurHash 计算。继续校验签名、TLS、下载目的地址及文件完整性，加密附件保持原字节。
- **客户端图片预览**：认证下载和缩略图允许跨域资源嵌入，使 Element 服务工作线程返回的图片能够显示。认证要求保持不变，匿名访问仍返回 401，旧匿名下载接口仍返回 404；其他 API 和页面保留原策略。
- **异步上传**：完成上传和查询状态都要求认证，读请求体前验证所有者，限制大小，流式写入和计算摘要，原子发布文件与完成状态，防止并发覆盖。上传限时 5 分钟，5 分 30 秒的租约允许中断后重试；每次尝试使用独立文件和令牌，旧进程恢复后不能覆盖新结果。

旧本地 UUID 房间的新事件保存可信的本地状态快照，已有历史只有在完整的本地前序事件链能够证明权限时读取。不会为旧事件捏造签名，缺失、跨房间、循环或无法解析的状态分支仍拒绝访问。

1 MiB multipart 的 20 次内存微基准显示，每次分配从 6,435,496 字节下降至 2,238,292 字节，减少 65.2%；分配次数从 74 降至 57。这是解析器微基准，不是网络吞吐结果。共享图片处理器的原图与缩略图字节等价性单独测试。

## 客户端与回归

客户端实验使用 Element Web 1.12.30 与 Synapse 1.162.0，保留 TLS 验证，使用独立账号及持久浏览器加密存储。基线验证双向明文和端到端加密消息，以及 PNG、普通文件的双向普通和加密附件传输；8 项附件均核对实际下载字节的 SHA-256。另检查长轮询被消息唤醒、未读数归零和历史翻页。

实验期间曾因共享磁盘耗尽导致 Synapse 下载失败。清理可重建缓存后，同一 MXC 下载成功且摘要相符；该次故障单独保留记录，不算作成功样本。规范事件数据约占 226 MiB，另有 redo、binlog 和临时文件；重建数据前需要至少 1 GiB 可用空间，不能用压缩或重建数据来改变前后比较条件。

交付版本完整后端回归通过 71 个测试包、6,611 项测试及子测试，42 项按环境条件跳过。交付版 5/5 内容一致性场景和 16/16 协议探测通过。性能测量版本上的真实 MySQL/HTTP 设备消息确认验证 26/26 通过：480 条目标投递、8 个并发同步请求，覆盖同游标重试、跨账号和跨设备隔离、新消息与旧确认交错，三个测试设备最终队列均为 0。

性能测量版本的真实 Element 复验中，双向普通和端到端加密消息 12/12 成功，无丢失、重复或解密失败；8/8 附件传输及 8/8 原生下载均匹配文件名和 SHA-256。长轮询在发送前已等待 168 ms，发送后 290 ms 收到事件，未读从 1 归零；两个客户端的普通及加密房间共四项历史检查均通过。以上是有限样本的功能结果。

交付版修复响应头后，在没有媒体响应覆盖的真实 Element 中，双向普通及加密房间的 4/4 张图片均正常显示，4/4 次原生图片下载摘要一致；匿名下载和缩略图均返回 401，旧媒体接口返回 404。测试会话更新凭据后关闭重开，原设备及加密密钥不变，旧端到端加密消息仍正常解密。普通文件的完整传输结果来自前述性能测量版本，响应头修复未改动其内容处理路径。

## 适用范围

这些结果用于定位当前实现的开销，并非容量承诺。3 秒闭环负载不能证明长期稳态或突发负载表现；3 次多房间请求不能给出可靠的尾延迟。真实客户端的少量消息和附件验证说明功能可用，不代表跨服务器吞吐上限。压测数据中的加密事件仅为不透明载荷，实际解密由 Element 的独立实验验证。

没有通过关闭权限、认证、签名或 TLS 校验换取速度。旧历史证据不足时应拒绝访问；完整协议认证、所有并发联邦分支、跨设备密钥恢复和音视频通话不在本次性能验收范围内。

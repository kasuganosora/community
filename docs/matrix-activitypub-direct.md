# Matrix 与 ActivityPub 私信

网页消息页与内置 Matrix 共用会话、成员和消息记录，可以主动创建面向 ActivityPub 账号的私信，也可以接收对方发起的 Direct 帖子。外部 Matrix 用户通过原生房间邀请与联邦加入明确选择非端到端加密的混合会话。Misskey 中对应“指定用户可见”的帖子及回复，不是 Misskey 独立的 Chat 功能。

## 收件人与投递

新会话由创建者明确选择成员，并确认非端到端加密。原先由入站私信生成的房间保留原参与者集合；要改变这类旧房间的成员，请建立新会话。每条新消息在接受时保存成员版本和明确收件人快照；正文中的额外提及不会增加私信收件人。普通 Matrix 房间、加密事件和内部桥接事件不会进入 ActivityPub 出站队列。成员退出、封禁、屏蔽或房间参与者异常时停止外发。

Direct 消息中明确列在 `to/cc`、但本站尚未保存的远端账号，会通过受限联邦获取进行解析。每次最多解析 32 个未知账号，总预算 20 秒；超限或失败不截断收件人后返回成功，而是回滚以待重试。公开消息不会因此增加远端账号抓取。

Misskey 2026.10.0 的实测群私信存在源协议限制：它本站的另一位收件人可能只出现在 Mention 标签中，而不出现在发送给 Community 的 `to/cc`。Community 不能据此判断该账号是否有权接收后续私信，因此不会把普通提及自动扩展为收件人。桥接保证的是原 ActivityPub 消息明确提供的参与者集合，不承诺还原远端服务器未公开的完整群成员。

客户端消息与持久化出站任务在同一数据库事务保存。后台事务创建 Direct 帖子、ActivityPub 投递任务和 Matrix 事件映射，重试不重复创建帖子，也不把自己发送的消息再次桥回房间。Matrix 接受消息表示已保存及入队，不等于远端服务器已经接收；远端投递继续使用现有 ActivityPub 持久队列。

只处理升级后客户端新发出的消息，不扫描或补发历史 Matrix 消息。旧房间的“回复留在 Matrix”说明会更新。混合会话不提供端到端加密，也不会把现有加密房间静默降级。作者撤回会删除对应联邦内容；编辑按删除旧内容后重发处理，不能保证远端尚未看到或保存旧版本。

媒体下载与帖子的收件人权限不同：Matrix 下载要求登录，但已取得完整 MXC 地址的其他登录用户也可能下载其内容；ActivityPub 附件使用不可猜测的下载地址。不要把匿名下载被拒绝误认为逐房间附件权限或端到端加密。

## 会话、成员与客户端反馈

网页通过 Community 登录使用 `/api/v1/chat/conversations`；Matrix 客户端可用 `/_matrix/client/v3/community/conversations` 创建和管理同一会话。普通 Matrix 客户端没有此扩展的创建界面时，可先在网页建立会话，再从客户端房间继续交流。

成员变更期间暂停跨协议外发，并在每次任务处理时重新检查当前授权。新成员不能读取加入前的历史；移除再加入也不会恢复旧任务的收件权限。远端回复若只授权给旧成员，不会直接投进已增加新成员的群。外部 Matrix 用户向 ActivityPub 发言使用标注完整 MXID 的本站代理 Actor，该身份没有独立登录凭据。

网页消息旁区分排队、失败和远端服务器接收；服务器接收不代表用户已读。作者可重试仍有权限的失败任务，不重新创建帖子。Matrix 客户端通过作者专用通知房收到失败及恢复提示，不把投递错误广播给原群；外部 Matrix 作者需接受该通知房邀请。管理员任务页只展示运行元数据，不开放私信正文。

回复沿可信同房间事件映射关联。作者撤回覆盖正文及关联附件。Unicode 回应与本站允许使用的自定义表情走现有回应模型；AP 自定义回应传入 Matrix 时保留 shortcode 和扩展元数据，标准客户端不一定显示图片。尚未复制到本站的远端自定义回应不能冒用本站 shortcode。Mastodon 的收藏也不等于任意表情回应：普通 AP Like 以带收藏元数据的 `Like` annotation 显示，Undo 撤回该标记，不增加自定义表情回应计数。

## 回复、附件与头像

回复通过同房间的事件映射关联到原 ActivityPub 帖子。本站附件必须是发送者拥有的 Matrix 媒体；外部 Matrix 附件仅接受已通过联邦授权的事件，MXC 服务器必须与发送者所属服务器一致，通过签名媒体请求导入。任意 URL、无关服务器及加密附件不进入此通道。下载失败保留可重试任务。敏感附件以带警告的普通文件传递，避免客户端直接预览；正文内容警告使用可折叠的 spoiler。对不支持普通文件预览的平台，AP 正文附上原有不透明附件地址的下载链接，不改变私信收件范围。

远端头像经过受限下载、图片解码及大小校验后提供真实的 Matrix 媒体地址；原来只显示名字占位符的成员可随新的入站消息更新。公开头像可跟随有限次数的 HTTPS 重定向，每一跳仍受 DNS、地址与证书检查。头像抓取失败不阻塞私信，也不会将失败来源标记为已经同步。Matrix 用户自行设置的头像优先保留。房间图标与成员头像是独立设置，默认房间名称的首字母不代表成员头像同步失败。

未设置头像时，以完整账号 `username@domain` 的 SHA-256 生成稳定的对称几何图案；域名统一小写，用户名保留大小写。同名但不同站点的账号使用不同种子。默认头像为固定 128×128 PNG，在请求时内存生成，不写数据库或文件；浏览器可以长期缓存。网页、ActivityPub 资料及 Matrix 默认头像使用同一规则。真实头像不受此默认机制影响。

- Matrix Homeserver 整包回归通过；最后的头像下载失败后恢复场景另经定向回归通过。
- 默认头像、serializer 与 ActivityPub 整包通过。默认图检查包括同账号稳定、域名区分、固定尺寸、无存储记录、非法媒体标识拒绝，以及客户端手动清空头像后的默认行为。
- 反向桥接覆盖事务回滚重试、重复事件、快速回复尚未完成投递的父消息、附件回复、已删除来源、精确收件人、退出或屏蔽后的拒绝，以及普通房间和加密消息不外发。

真实 Misskey 实验实例已接收到 Matrix 客户端发出的 Direct 回复，回复正确关联原帖子；重复客户端事务没有产生重复远端帖子。PNG 和普通文件均实际送达，Misskey 下载结果与原文件 SHA-256 相同。为避免可猜测的私信文件路径，联邦附件展示名使用不透明文件名，原名保存在描述中；不承诺远端展示原文件名。

受控签名 ActivityPub 服务与真实 Matrix HTTP 接口另验证了头像变更、`icon:null` 清空后动态默认头像、图片不可用时仍送达私信，以及用户自选头像保留。已知 MXC 地址的跨账号下载边界按上文记录，不能将匿名拒绝测试当作房间级媒体隔离证明。实验记录保存在本次工作区 `/tmp/community-feed-qa/matrix-avatar/`；前端自然入口截图和浏览器报告见 `/tmp/community-avatar-qa/`，凭据不入仓库。

升级前桥入的附件事件可能没有新的可信回复映射；此类回复不会猜测匹配或补发旧消息。可以在同房间发送新的普通消息，或回复有映射的文字消息。

### 会话名称与国际化账号

单人跨协议私信使用对方的显示名和完整账号作为 Matrix 房间名称；多人会话展示部分成员及总人数。服务启动时会更新已有的默认会话名，手动设置的名称保留。成员变更或新入站私信也会刷新自动名称。

前端账号中的国际化域名按 Unicode 显示（例如 `xn--s8w913fdga.chn.moe` 显示为 `铜锣湾.chn.moe`）；导航、API 请求和联邦标识继续使用原始账号。

### 退出私信房间后的新消息

由入站私信自动生成的房间中，本地收件人主动退出后，下一条新的私信会重新邀请其进入原房间。邀请等待用户接受，后续消息不会自动替用户加入；重复处理已经投递的消息不会重新邀请。账号屏蔽、房间封禁和管理员踢出仍然有效。显式创建的混合群组沿用成员管理规则，退出的成员不会因为新消息自动恢复。

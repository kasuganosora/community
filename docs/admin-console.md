# Community 管理后台

具有后台权限的本地账户登录后，可从侧栏或「设置 → 管理后台」进入自己有权访问的管理页面。后台参考 Misskey 的分组导航与分区表单，使用 Community 自己的配色和组件；独立布局不显示时间线侧栏、推荐关注或手机发帖按钮。

## 权限边界

超级管理员具有全部已实现管理能力。角色可以分别委派概览、用户、举报、联邦、设置、规则、公告、表情、邀请、角色、系统、审查日志、文件、品牌及 Webhook 等能力；导航和前端路由按这些能力筛选，服务端仍独立检查权限和当前账户状态。OAuth 调用还需对应管理 scope，不能仅凭前端隐藏按钮保证权限。

角色管理不能授予操作者自己没有的能力，不能通过该接口设置 `User.IsAdmin` 或创建保留的超级管理员位；包含不支持权限位的旧角色受到保护。整站迁移仍仅限超级管理员。账户停用、封禁和角色变更的效果应以服务端后续请求重新校验为准。

## 统计口径

`GET /api/v1/admin/analytics` 接受 `days=7` 或 `days=30`，日期按 UTC 计算，热力图固定返回最近 180 天。界面提供图表、数值提示和可展开的数据表。

- 账户和表情总量区分本地与远端；实例数是已收录远端账户中的不同域名数。账户数量不是人类用户去重人数。
- 帖子总量和每日趋势基于仍保存的记录，排除已删除及定时待发内容，包含转发、私信和已收录远端帖子。管理图表只返回聚合数字，不返回正文。删除帖子会改变过去日期的曲线，当天数据尚不完整。
- 每日活跃账户是当天发布过帖子的不同本地账户数，包含转发；不是在线人数、登录人数或阅读人数。没有历史在线记录时明确显示不可用。
- 注册周队列按 UTC 周一分组，只展示注册周和后续观察周均已结束的最近 12 个队列。留存指注册周结束后的 7 天内至少发过一次帖子的账户；不是以当前最后活动时间代替历史行为。没有注册账户的队列不计算百分比。
- 联邦关注分布分别统计「本站关注远端」「远端关注本站」，只含已接受关系及未删除账户，每个方向展示前 20 个域名。

旧 `dimensions`、`measures`、`retention` API 保留兼容。`measures.total` 是完整十进制数字字符串，新增／活动用户采用过去 30 天窗口；旧 `active_users` 使用账户 `last_activity_at`，与新图表的发帖活跃指标不同。`opened_reports` 是举报总量，待处理数由总量减去已处理数。旧 retention 的日／周队列采用「队列结束后有发帖」口径，与新 analytics 的限定下一周观察窗口不同，不应混用。

统计查询传递请求取消信号；新分析接口设置查询超时，不把数据库失败转换成空图或零值。迁移复用已有 `accounts(created_at)` 索引，缺少时补充，并检查／创建 `statuses(account_id, created_at)` 的有效前缀索引，避免重复同等索引。超大站点仍需结合真实查询计划和数据量监控响应时间。

## 设置保存与生效

| 分区 | 生效方式 |
| --- | --- |
| 常规 | 站点名称、介绍、联系邮箱保存后供新请求读取 |
| 品牌 | 站点缩略图 URL 用于公开介绍；不会替换历史文件、账户头像或仓库 Logo；只接受 HTTPS，保存不主动下载 |
| 注册管理 | 开放注册、审核、邀请码、邮箱验证和注册提示影响新注册；不改变已有账户状态 |
| 安全 | 验证码配置使用专用接口；环境管理项只读，密钥不回显 |
| 性能 | 有范围限制的默认分页条数，仅作用于未指定 limit 的请求，不突破各接口最大值 |
| 邮件、对象存储、搜索 | 可保存部署配置，重启后用于相应服务连接；环境变量／显式部署配置优先 |
| 外部翻译 | 仅展示部署类型和凭据是否配置；不等于连接已验证，也没有无效的启用开关 |
| 数据库 | 当前驱动和连接池诊断，只读；没有 SQL 执行器、数据库密码或在线切库功能 |

字段会说明来源、是否只读和是否需要重启。部署控制的字段不能用后台保存覆盖。秘密字段只显示是否存在；未修改时应省略，清除须使用明确的清除操作，不把空输入当成替换已有密钥。

### SMTP

先保存服务器、端口、认证方式、用户名、密码及发件人配置，再执行连接测试。测试使用保存后的有效配置验证连接、TLS／认证，不发送邮件，不证明邮件最终投递或收件箱可达。隐式 TLS 通常对应 465 端口，STARTTLS 通常对应 587，须按邮件服务实际要求匹配。新发送配置需重启生效；明确环境变量仍优先于数据库配置。

### S3／MinIO

管理员必须预先建立目标 bucket 并配置所需访问权限和公开媒体访问方式。后台连接测试只检查现有 bucket 是否可访问，**不会自动创建 bucket、上传测试对象、删除对象或修改 public policy**。测试成功不等于所有写入、删除或公开下载权限均已验证。

存储切换需重启，不会自动搬迁旧媒体或修复历史 URL。切换前应独立验证上传、读取、删除及公开 URL，并保留旧文件可达性。后台填写的网络端点受安全连接约束；明确由部署环境控制的内部服务地址通过部署配置管理，不应通过绕过 TLS 或地址校验来让测试通过。

## 队列、Webhook 与审查日志

作业队列展示的是持久化 ActivityPub 投递和 outbox，不是通用后台任务调度器。重试／取消仅针对待处理或失败任务；运行中、已完成或状态已改变的任务返回冲突，需要刷新。取消不会撤回远端已经收到的活动；重试仍须经过实际网络投递，不能以「已排队」代替成功。

Webhook 从已提交的 federation outbox 捕获事件，支持 `status.created`、`status.updated`、`status.deleted`；只有明确为本地、公开、非 local-only、非定时、非转发的合格帖子快照进入投递。它不是全部站点事件订阅，也不发送私信、仅粉丝帖子或正文。删除重发会对应删除和新建事件，不承诺产生更新事件。新订阅从创建时的 outbox 游标之后开始，不回放全部旧事件。

订阅地址须为不含凭据的 HTTPS 公网地址，并受连接／重定向安全检查。秘密值只在创建或轮换时返回，接收方应妥善保存。投递包含以下头：

- `X-Community-Event`：事件类型。
- `X-Community-Delivery`：持久投递 ID，应作为接收方去重依据。
- `X-Community-Timestamp`：请求签名时间。
- `X-Community-Signature`：`sha256=` 加 HMAC-SHA256 十六进制值，输入为 `timestamp + "." + deliveryID + "." + 原始请求正文`，密钥为订阅秘密。

接收方应验证签名、限制时间偏差，并按投递 ID 幂等处理。后台投递有租约、重试和持久状态，无法保证外部副作用恰好执行一次；接收方返回 2xx 才记为成功。自动失败退避以尝试次数平方的分钟数计算，达到 5 次失败后转为失败状态；管理员可对允许状态执行手动重试／取消。测试操作创建独立 `webhook.test` 任务，排队成功不等于远端接收成功。

审查日志记录操作者、操作、目标标识、结果和耗时，不保存请求正文、完整 URL、IP 或凭据。`pending` 表示执行或最终结果尚未确认，包括进程中断情形；不能视为成功。它覆盖接入审计的管理写入路由，不是对数据库直接修改或系统外操作的全量取证记录。

## 公告、广告、头像挂件与文件

公告区分保存草稿与发布状态，成员端按发布时间／显示范围读取；读取记录与公告更新时间比较，内容修改后可以重新成为未读。撤回与删除不会等同于发送通知或向外站广播。没有承诺公告邮件群发或跨站公告同步；公告反应接口明确返回不支持，不把空反应列表视为已实现互动。

广告和头像挂件上传复用安全图片处理，保留本站托管资源，拒绝任意远端图片 URL 和脚本内容；当前上传上限为 2 MiB，仍受解码尺寸和格式检查。广告链接仅允许有效 HTTP(S) 地址，前台标注「广告」，外链使用 `sponsored noopener noreferrer` 和无 referrer；没有点击／曝光计费、用户画像或广告投放平台集成。用户侧仅展示启用且在有效时间范围内的最多 3 条广告，卡片位于有右侧栏的布局，定期刷新，不保证所有视口都有广告位。

普通成员可选择已启用挂件或恢复普通头像；停用挂件停止可用展示，删除会清除使用者关联。挂件是附加图层，不重写原始头像文件；不宣称与外站原生头像装饰协议兼容。

文件管理不会通过删除附件连带删除帖子或私信。仍被帖子、头像／背景图引用或与其他附件共享存储的文件会拒绝单独删除，并说明原因。当前清理路径针对本站上传目录，不是 S3 全量垃圾回收或远端文件删除工具；数据库记录和对象存储实际字节应分别核查。

## Logo

新标志将 Community 的首字母 C 与对话气泡合并，以透明负空间适配深浅背景。`frontend/public/logo.svg` 与 `LogoIcon.vue` 使用相同矢量路径，favicon 与页面标志保持一致；没有运行时图片生成或外部图标请求。

## 运维与验证

启动时执行已注册的 `AdminManagementScript` 迁移，为审查日志、公告／已读、头像挂件、广告、Webhook 订阅／投递及账户挂件字段补齐表结构。迁移可重复执行，保留已有记录；不提供会删除审计与投递历史的自动回滚。

前端在 `frontend` 执行 `npm ci`、`npm run lint`、`npm test`、`npm run build`。后端需验证管理权限、数据聚合、设置生效、队列状态竞争、Webhook 安全、资产引用和迁移幂等。真实浏览器验收使用独立账号和内容，覆盖管理员、有限角色、普通成员、桌面／手机布局、失败重试及实际用户侧效果；不要拿真实用户数据试验删除、封禁或迁移。

**历史基线，不是本轮扩展验收结果：** 初版后台曾通过前端 50 个文件／202 项测试，以及 admin、report、middleware、account、serializer、common、captcha 七包回归；Chromium 检查过 1440／390／320px 的 8 个旧管理页面、深色主题、手机导航、普通成员访问限制及部分管理闭环。当时未向外部添加中继或执行整站迁移。这些数字不能证明本轮新增页面、Webhook、广告、角色委派或存储切换已通过真实验收。

本轮扩展验收（2026-10-07）：前端 59 个测试文件、231 项测试通过，lint、类型检查与生产构建通过；后端 13 个相关包回归通过，日期扫描修复另通过 3 项定向回归。Chromium 检查 27 个管理页面在 1440／390／320px 下的 81 个页面组合及深色主题，无页面异常、失败管理请求或整页横向溢出。真实角色／邀请 API 与浏览器检查 37 项通过，文件／挂件／广告 15 项通过，公告、已读持久化、撤回、设置实际生效与审计 5 项通过。MySQL 趋势合计与 SQL 聚合一致；Webhook 通过真实 HTTPS、独立 HMAC 验签、503 重试、8 并发只投递一次、重定向拒绝和禁用检查。未把连接诊断当作实际邮件送达或对象存储切换验收，也未在本轮执行整站迁移。私有测试凭据与运行日志不提交仓库。
